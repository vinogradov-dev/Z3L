# U104 — the pull's card is one lettered field, and its keys are the commit

## What was measured

- `Document::height_view` (`app/src/document.rs`) built the pull's card with
  `ToolView::height(Message::CmdSetExtrusionHeight, …)`, which sets `actions: true`: a title word
  above the row, `mm` beside the number and the ✓/✕ pair under it — the surface the owner called a
  dialog.
- `ToolRow.label` was `Option<Message>`, a word. The sketch plate's rule (`point_fields::FieldParam`)
  already had the pair this needed: a `FieldLabel::Symbol("H")` names the quantity and no unit is
  drawn, because the symbol says it.
- The card's field never held the keyboard: `ExtrudeGizmo::take_focus` returned `true` once and the
  shell handed that to `Scrub::focus`, but `egui` 0.37 builds a widget after it is asked for the
  focus, so the request of the frame a new `Area` appears is dropped (`Memory::end_pass`'s
  dead-man's switch, and `interested_in_focus` runs before the widget exists). `distance.rs` worked
  around the same fact by asking again while nothing had the focus; `point_fields.rs` already counted
  its asks (`FOCUS_REQUESTS: u8 = 2`).
- Consequence of that: typing a height into the card wrote nothing. `apply_tool_outcome` sent the
  edit to `preview_extrude`, which built the overlay from the typed number but never stored it in
  `Pull::height`, so the next frame's field and arrow snapped back to the dragged height and the
  scene kept a preview the card no longer showed.
- Enter was read by `handle_keys` before the card drew, so with a focused field it either did
  nothing (`text_edit_focused`) or finished the pull at the *previous* height. `Scrub` reads Enter
  for its own text (`FieldOutcome`), and `point_fields` and `distance.rs` both report their keys
  after the field drew, which is the ordering M71 fixed for the old command bar.

## Decisions

- **`ToolView` names how the commit is offered** instead of a boolean: `ToolCommit::{Pair, Keys,
  Gesture}`. The ✓/✕ pair, the gesture's keys alone, and neither (a fill commits on its click) are
  three states of one question; `actions: bool` could not say "has a commit but draws no button",
  which is exactly the pull.
- **`ToolView::lettered_height(symbol, …)`** builds that plate: no title, one row whose label is
  `FieldLabel::Symbol`, `unit: ""`, `commit: Keys`. `body` draws a row's label when it has one, so a
  single-row card is named without a title.
- **`ToolRow.label` is `Option<FieldLabel>`**, the enum the sketch plates already use, rather than a
  second word-or-symbol enum in `tool_card`.
- **Enter in a focused field is the tool's commit.** `Scrub` reports `FieldOutcome::submit`, `row_ui`
  passes it up, and `body` turns it into `ToolOutcome.action = Some(Apply)` for a view that has an
  explicit commit. `apply_tool_outcome` already runs the edits before the action, so the command
  writes the number Enter just made — the M71 order, now that the card is the surface that owns it.
- **`preview_extrude` adopts the height it previews** (`ExtrudeGizmo::set_height`), so the arrow, the
  field and the overlay are one number (ADR 0119: "the preview follows the typed number immediately").
- **A fresh pull asks for the keyboard on two frames** (`FOCUS_REQUESTS`), the count `point_fields`
  uses, so the field is typeable without a click and does not hold the keys afterwards.

## Ruled out

- Keeping the ✓/✕ pair and adding the symbol: the pair is what the owner asked to remove — the
  gesture already has Enter and Escape, and a card that offers both is a dialog.
- A unit of `mm` on the lettered plate: `H` already names the quantity, and `mm` beside a 76 pt box
  is the second word the owner wanted gone.
- Removing the title but drawing the row's label only when `rows.len() > 1`, as `body` did: a
  one-row card would then be a bare number. The label rule now follows the row.
- Reading Enter in `tool_card` (a second key reader): the card reports what its own focused field
  saw, and `handle_keys` keeps Escape, Tab and the unfocused Enter, as ADR 0076 says.
- Re-asking for the focus whenever nothing has it, the way `distance.rs` does: a card that lives
  longer than a fill would take the keys back after every click in the scene.
- A `ToolView` per surface (a card view and an inspector view): ADR 0119 keeps one view for both, and
  the inspector shows the same lettered `H` row above the body's card.
