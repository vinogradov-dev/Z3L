# U115 — the status bar reports, and what left it found a home

## What was measured

- `app/src/status_bar.rs` drew nine controls in a 28 pt row (`theme::STATUS_HEIGHT`): the five-cell
  transform band, the contour's along/free switch with *Apply* and *Cancel*, the draft's *Close*,
  *Finish* and *Cancel*, the ✕ that cleared the creation parent, the niche's and the navigation's
  *Done*, and the snap's `selectable_label`.
- The band was 431 pt in the longer language (U113, X88) and the row keeps `COMMAND_ZONE_MIN = 448`
  for it, so on the narrowest window (640 pt) the band and the readouts already fought for the row;
  X94 answered that with three clipping zones, not with fewer controls.
- `crates/ui/src/tool_card.rs` already had a one-number card, an inspector section and the ✓/✕ pair
  (`ToolCommit::Pair`), and `Document::show_tool_card` drew it at the pointer for a box, a pull and
  a fill. `ToolView` had no way to draw a tool that asks for no number.
- `crates/ui/src/container_card.rs` already armed a container (`ContainerAction::AddChild` →
  `Editor::arm_creation`) and knew nothing about the arm being live.
- The header's right cluster was four icon cells drawn right to left inside
  `Sides::new().height(36).shrink_right()`, and the tab row was laid out from the row's left edge
  with no limit: it grew under whatever was pinned to the right.
- `Message::FinishEnter` and the along/free words existed with no surface beside the bar;
  `Message::DoneEsc` had exactly one caller, the navigation button, and died with it.

## Decisions

- **The bar is text.** `StatusInfo` lost `mode` and `creation_parent`, `StatusOut`, `StatusAction`
  and `Document::apply_status` are gone, and `status_state_ui` became `status_command_ui` returning
  nothing. What is left is the three zones of X94, unchanged, around text only.
- **The band is the header's right cluster**, added last inside it so it is the cluster's leftmost
  control beside the tab row, with the gear on the far edge as before. `HeaderState::mode` and
  `HeaderAction::SetMode(TransformMode)` carry it; the shell writes `Shell::mode` from the header
  action, exactly as it did from the bar.
- **The band's cells print their word, not their key** (`TransformMode::cell`). Five keyed cells
  measured 431 pt; the header also carries the mark, the file actions, the tab row, four switches
  and the gear. The key is in the hover (`icons::tool_hint(hint, key)`), the node menu and the
  Settings page, and the five bindings are unchanged.
- **The right cluster's width is measured on a hidden pass** (`cluster_width`, the technique
  `readouts_width` uses) and handed to `tab_row`, which draws inside a scope clipped to its room:
  the strip elides and clips at the switches' edge rather than growing under the band. At 640 pt the
  left group and the cluster leave the tab row ~4 pt in both languages, so the strip disappears at
  the minimum window; in Russian the last two history buttons are cut with it. The band wins there
  because the owner asked for it to be always visible, the history buttons keep their keys and the
  File menu, and the alternative — a responsive header that hides items by width — is a design of
  its own (`plan/debt.md`).
- **A tool that asks for no number draws one row** (`ToolView::actions`): the draft's tool
  (`DrawTool::label`) with ✓ = `commit_drawing` and ✕ = `cancel_drawing`, and the contour edit
  (`Message::ContourEdit`) with the along/free switch (`ToolView::toggle` → `ToolOutcome::toggle`)
  and ✓ = `apply_contour_edit`. The card is drawn only for a draft `DrawDraft::is_complete` accepts,
  so a check never answers with a refusal. `ToolCommit::Pair` now carries its two words, because a
  draft's check is *Finish* and a contour's is *Apply*.
- **The creation parent lives in the container card**: `ContainerCard::show` takes `armed` and
  returns `ContainerAction::ClearChild` for *Create at the scene root again*. The editor owns the
  arm, so `cards.rs` reads and writes it; the status bar no longer names it.
- **Close stayed where it was**: the ribbon's Sketch→Draft cell and a click on the first draft
  point. The card carries the commit and the drop, which are the two the bar held for every tool;
  a second *Close* on the card would be a third button on a row measured for two.
- **No new `Place`.** The transform modes are `ACTIONS` rows with no place column; the contour
  edit's ✓ is `panel.outline.set`, `object.contour.replace`, `object.path.replace` and
  `panel.machining.update`, so those four rows gained `Place::ToolCard`.

## Ruled out

- A drop-down band that shows the armed mode and opens the five: two presses for one gesture and a
  popup over the scene, where the band is a single press.
- Hiding the band below a width threshold: the owner's requirement is that it is always visible.
- A ribbon cell for the along/free switch: the ribbon would need a new icon, a new method id and a
  tab that may be folded away, and the switch belongs to the running edit.
- Keeping the ✕ in the bar behind a smaller chip: the arm is a property of one container, and the
  card of that container is where it is readable and clearable.
- Making the bar's own controls narrower instead of moving them: X94's measurement showed the row
  has no room for a control beside a readout at 640 pt; the fix is a different surface, not a
  smaller button.
- An ADR: every move is reversible and none changes the document, the file format or the layer map.

## How it was verified

- Headless, on the bar: an idle frame, an armed draft, an armed contour edit, the ruler and the
  niche all draw labels only — the accessibility tree of each frame holds no control — and none of
  them draws a `✕`, a *Close* or a *Done*; the snap line is a label whose ink differs between its
  two states; the three zones still clip at 640 pt in both languages.
- Headless, on the header: the five cells draw in `TransformMode::ALL` order in both languages, a
  click returns `SetMode(Object)`, the band names itself as one `Role::Group`, and at 640 pt the
  file menu keeps a painted rectangle, nothing of the left group paints under the band, and the
  open scene's name survives in English.
- Headless, on the card: a draft and a contour edit each draw one row (no number), the ✓ and ✕
  report *Apply* and *Cancel*, the switch reports its press, a draft's ✕ writes no revision, the
  contour's check ends the edit and the press flips the motion.
- Headless, on the container card: *Add child* returns `AddChild`, an armed container names itself
  and *Create at the scene root again* returns `ClearChild`.
- Offscreen, with the real shell at 1280 × 800 and 640 × 480 in both languages: the band reads as
  one control beside the view switches, the placeholder cell of the object move keeps its glyph, the
  bar is three zones of text, and the snap line is the only bright readout while it holds. The
  narrow Russian window shows the trade-off above: *Файл* is the last left-hand control that fits.
- One finding left for the debt file: a widget inside an `egui::Area` is absent from the
  accessibility tree (found while aiming a test at the card's ✓), so the tool card's buttons are
  invisible to a screen reader. `plan/debt.md` carries it.
