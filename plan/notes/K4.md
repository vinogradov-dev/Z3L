# K4 — What was measured

## What was measured

- `crates/model/src/catalog.rs` held two material records, a `Catalog` with a uniqueness check and a
  wire form per record with `deny_unknown_fields`; `CatalogError` carried a `MaterialId` in every
  variant, which is why a stock block validated *inside* the material record and not on its own.
- `crates/export` builds every table from one column list: `table::TABLES` feeds the manifest
  declaration, the JSON Lines writer and the CSV copies. The eleven tables were `products`, `nodes`,
  `parts`, `banding`, `contours`, `facades`, `fittings`, `machining`, `materials`, `classes`,
  `properties`; `materials` had no stock column and `parts` had no price.
- The K2 note recorded exactly what was missing: `stock_group` was omitted and `grain` was stated as
  `none`, because the catalogue carried neither a stock group nor a sheet size. ADR 0095's
  consequences name the same gap: "sheet sizes and prices are not in the catalogue yet".
- `docs/domain/order-export.md` §4 already promised "money in minor units, with the currency in the
  manifest", and §6 promised the declared rules (kerf, trim, sheet sizes) in the manifest — the
  contract document described a future the code had not reached.
- `Catalog::new` had eight call sites outside the model (testkit, the app's `default_catalog`, five in
  `engine` tests, one in `export` tests); `PanelMaterial::new` had no stock parameter, so no call site
  would have to change shape if the stock arrived as a chained constructor.
- `Length` is integer micrometres with a transparent serde form, `Panel::MAX_LENGTH` is ten metres and
  `Panel::MAX_THICKNESS` one metre — the maxima a sheet can reuse.

## Decisions

- **A stock block per panel material, and the currency on the catalogue.** `PanelStock` holds the
  sheet, the optional group and the optional price; `Catalog` holds the optional `Currency` (code and
  minor scale). A priced material without a currency is refused, because a number with no unit is not
  money. The price is `Money(u64)`, so a negative price is unrepresentable.
- **`PanelMaterial::new` keeps its five arguments and `with_stock` chains the block**, so the eight
  call sites that do not stock anything stayed untouched.
- **The stock types are built, not deserialized, by themselves.** `StockWire` and `SheetSizeWire` are
  private raw forms read by `PanelMaterialWire`, so a refused sheet can name the material it belongs
  to; a nested `Deserialize` would have surfaced a `StockError` with no material id.
- **The `sheets` table is a plan, not a layout.** One row per stocked material the order cuts from:
  sheet, usable rectangle after the per-side trim, price, part count and part area. No positions and
  no sheet count — a count from an area ratio is a nesting strategy with 100 % efficiency, which
  ADR 0095 forbids. The manifest declares `kerf_um` and `trim_um` so the reader applies them.
- **A part's price is its core area of the priced sheet**, rounded once in i128; a product sums its
  parts. Zero means "no price", the same convention as `material_id = 0` and `depth_um = 0`.
- **The saw rules are constants in the exporter** (4 mm kerf, 10 mm trim per side) because a saw is not
  catalogue data and no shop setting exists; filed as debt, and the contract block is already in place.
- **The application's default catalogue gets sheet sizes and stock groups but no price and no
  currency**: inventing the shop's money is not the sample catalogue's job. The testkit sample does
  carry both, so the golden package exercises the columns.
- The package major version stays 1: columns appended, one table added, blocks added. `--no-timestamp`
  still produces byte-identical goldens, and `FURNICRAFT_UPDATE_GOLDEN=1` regenerated it.

## Ruled out

- A `sheets` row with a computed sheet count or with part positions: a nesting strategy inside a data
  contract, and the package has no layout inputs.
- A price on the edge-banding material: a roll is bought by length, so its price needs a unit the
  contract does not have yet; the four new `materials` columns write zero for an edge row.
- A `settle`-style currency table in the exporter (JPY = 1, KWD = 1000): the catalogue declares its own
  minor scale, so no currency list lives in our code.
- Putting the stock on `EdgeBandingMaterial` for symmetry: no consumer needs it and the unit is wrong.
- A builder crate or a `CatalogBuilder`: three optional values on one record do not need one.

## Next

Nothing in K4 waits. A workshop setting for the saw rules and a roll price for banding are filed in
`plan/debt.md`; the catalogue editor is the task that would let a person fill a stock block without a
text editor.
