# O9 — The six steps, the family a record stands in, and the name of the step that failed

## What was measured

- Nothing selected anything. `crates/engine/src/resolve.rs` resolved a panel's thickness and banding
  from the directory and had no notion of a slot; `catalog` had `Family { code, slug, label }` with no
  rank, and `NomenclatureItem` carried no family at all, so "the plug that belongs to this corpus" had
  no data to read.
- `§6` put the rank on the family row and then said it orders the records inside the family, which one
  row cannot do; `§3`'s envelope table listed no family field, and `§15` named `family_members`,
  `by_external` and `select` as queries that did not exist.
- A node's properties accept any key but only type-check the reserved ones, and `PropertyValue` had
  `Reference { id: Id }` for a *document* id and nothing for a catalogue record — so a person's choice
  had no legal value to be stored in (§10 wants it on the node).
- `PropertyRegistry` was not exported from `catalog` although `Directory::new` takes one, so neither a
  test nor any other crate could build a directory.

## Decisions

- **The member carries the rank.** `NomenclatureItem { family: Option<FamilyCode>, rank: Option<u16> }`,
  the family row keeps `sample: Option<ItemId>`, and `Directory` refuses a rank twice in one family, a
  rank with no family, an unknown family and a sample that is not one of its own members. That last
  rule is what makes "from the sample outwards" measurable instead of decorative.
- **`PropertyValue::Item { id: ItemId }`** at schema 28, with the golden regenerated: a catalogue id is
  not a document id (ADR 0148), so a reader never has to guess which of the two a reference means.
- **`SlotId` is a vocabulary of its own** — lower-case letters, digits and `.`, `-`, `_` between them —
  because `Slug` refuses the dot `§10` writes (`plug.confirmat`) and a slot is not a path.
- **The six steps are `Directory::select`**, a pure function over the registries: a choice is never
  overruled (a record of another kind is a refusal, not a fall-through), the anchor's family filters,
  the nearest rank to the sample answers, the anchor's `default` property is step five, and the rest is
  a `Miss` naming the anchor, the slot and the step.
- **The cache is keyed by node and slot and stamped with both revisions.** A selection depends on the
  document *and* on the directory, and the directory moves on its own schedule (§13), so one stamp
  carrying both is the only key that cannot answer a stale record. The engine owns the type; the
  surface that asks will own one instance.

## Ruled out

- **A rank on the family row**, as `§6` first read: one row cannot order many members.
- **Storing the choice as a `Text` of the item id** — a stringly-typed reference in a document that
  keeps typed values everywhere else.
- **`PropertyValue::Reference` reused for a catalogue id** — the two kinds are resolved by different
  ports and one is absent from the directory while the other is absent from the scene.
- **A "Plug" row in the panel card now** — the hardware that raises a slot is O10 and O13; a card
  invented ahead of it would be a row with nothing behind it. `plan/debt.md` holds the gap.
- **Reading the choice from the card's draft** — the choice is document data written by a command, so
  the card will read it from the node like every other property.
