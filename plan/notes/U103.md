# U103 — a rubber band is a silhouette test, not a second picker

## What was measured

- A click selected one node and nothing selected several: `Editor::select_viewport_hit` took one
  `Option<Id>` and `Selection` held an ordered `Vec<Id>` since U102, so the multi-selection existed
  and only the gesture was missing.
- The picker measured the ray, not the outline: `SceneFrame::pick(ray, height)` tests triangles and
  line chains (`crates/scene/src/ray.rs`), and nothing in the crate projected a shape to the screen.
  `Camera::project_ndc(point, aspect)` does, and `app/src/gizmo_math.rs::screen_point` is the shell's
  point-space wrapper for it.
- `SceneFrame::pick` ended with the product envelopes (ADR 0100), so "empty space" inside a closed
  piece was not empty at all: `pick` on any point in the demo scene returned an id. A band that
  reused that answer could never start inside a cabinet.
- `egui` 0.37 reports `drag_started_by` / `dragged_by` / `drag_stopped_by` and keeps
  `pointer.press_origin()` while the button is down, so the gesture needs no threshold of its own and
  a click can never be mistaken for a band: a release egui calls a click is the existing click path.
- `Document::viewport` computes `consumed_click`, `previewed` and the gizmo drags before the click
  block, so the band can be armed there with every other gesture already claiming its press.
- `theme::helper` is the guide amber and `scene::SELECTION_LINE_COLOR` the cyan the selected objects
  are drawn in; `theme.rs` had no band ink, and `cargo xtask ui-rules` refuses a literal in a feature
  module.
- `app/src/ui_shots.rs` renders the real frame offscreen with an `#[ignore]`d test and this machine
  has an adapter, so the band's fill and its two outlines were looked at as pictures.

## Decisions

- **The geometry lives in `scene`, the rule in `ui`.** `SceneFrame::band_hits(camera, aspect,
  NdcRect)` returns `(Id, BandCoverage)` for **every** shape — `Inside`, `Touched` or `Missed` — in
  normalized device coordinates, so no `egui` type enters the scene and a `Missed` entry is what lets
  the caller tell "all of this object is inside" from "one board is". `Editor::select_band` groups
  those by `resolve_viewport_pick` and applies the rule the drag's direction chose.
- **Whole object, not shape.** A window needs every shape of the resolved object inside; a crossing
  band needs any shape to reach it. Without the `Missed` entry the first rule silently degenerated to
  "any shape inside", which took a closed cabinet from a band around one of its boards.
- **The silhouette is the convex hull of the projected vertices.** A box projects to the hull of its
  eight corners, which is exactly the outline the viewport draws; a screen-space bounds test would
  take a rotated shape in the empty corners of its bounds. `crates/scene/src/band.rs` holds the
  monotone chain and the hull-versus-rectangle test (vertex inside, corner inside, edges crossing).
- **`pick_surface` is the new question a band asks.** `pick` minus the envelopes, so the empty part
  of a product is empty space for the rectangle while a click there still selects the piece.
- **The dominant axis decides window or crossing**, rightward or downward enclosing, leftward or
  upward touching. The owner's sentence named both axes and a diagonal has to answer one way, so the
  axis the drag mostly travelled decides.
- **Band ink is the selection ink**, derived in `theme::selection_band` from
  `scene::SELECTION_LINE_COLOR` with a 26/255 fill, because the band and the objects it takes must
  read as one thing; a guide is amber and never a selection (ADR 0111).
- **Escape drops a live band** in the ordered key path, before leaving a container level, so a cancel
  writes nothing and the release selects nothing.

## Ruled out

- A ray cast per shape on release (the "pick every pixel" approach): a band is a screen rectangle and
  the question is a 2-D outline overlap, so probing the ray grid would be slower and would still miss
  a thin path between two probes.
- Screen-space axis-aligned bounds instead of the hull: the diamond test in
  `crates/scene/src/band.rs` (`a_band_reads_the_silhouette_and_not_the_screen_bounds`) pins the
  difference, and the bounds variant takes objects the band visibly does not cover.
- An inventory row for the band: it is a gesture with no button, no label and no place, so it adds no
  capability; an invented row would claim a place the ribbon does not draw.
- Reusing `pick` for the band's start and treating an envelope hit as empty space by exception in the
  shell: the exception belongs in the frame's own question, not in a caller.
- A private threshold for "did the pointer travel": egui's click distance already decides, and a
  second number is a second answer to the same question.
