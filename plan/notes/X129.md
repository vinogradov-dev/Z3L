# X129 — the append-only guard on a reference file

the append-only guard on a reference file

## What was measured

- `cargo xtask file <path> --body <text>` took the whole body of `plan/map.md`, `plan/debt.md`,
  `plan/questions.md` and the rest, so the body a session passes is also the body that deletes: the
  gate reads an entry as free text, and a file that lost half of them is a shorter legal file. The
  `[plan]` debt entry described it, and X129 landed the guard and took that entry out.
- The entries of both append-only files are top-level `- ` bullets with their wrapped lines indented
  two spaces; blank lines separate most of them but not all (two entries sat adjacent in
  `plan/debt.md`), and `crate::parse::markdown_bullets` already reads exactly that shape for the task
  report and the debt selection.

## Decisions

- The guard compares entries, not bytes: an entry is a bullet with its wrapped lines joined and
  whitespace collapsed, so a body that re-wraps an entry at another column still holds it. Rewording
  an entry counts as dropping it — append-only means the text stays — and `--replace` is the way in.
- `--replace` is the flag name, and a whole-file rewrite is the only way an entry leaves, because
  `plan/debt.md` drops one when its fix lands and that is a person's deliberate act rather than a body
  that forgot it. This task's own entry left through `--replace`.
- The list is `plan/debt.md` and `plan/questions.md` (`APPEND_ONLY`). `plan/map.md` and the rest are
  not on it: a map row is edited and deleted freely, and only an accumulating file has entries a body
  can silently lose.
- The refusal quotes the first twelve words of every entry that would leave, with the inline-code
  backticks stripped so the entry's own quoting cannot nest inside the message's.

## Ruled out

- A size guard ("refuse a body far shorter than the file") is the other half the debt entry offered;
  it passes a body that is short but complete and refuses one that legitimately adds nothing, so it
  catches the accident only by luck.
- An `--add <entry>` verb that appends one entry: it is a second way to write the same file, with its
  own splicing and its own gate run, and a session that means to append now passes the file's own
  entries in the body safely.
