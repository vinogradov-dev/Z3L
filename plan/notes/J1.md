# J1 — the headless command channel, and what it cost

## What was measured

- `app/src/cli.rs` (278 lines) carried one subcommand: `export`. `Session::dispatch`,
  `dispatch_in` and `begin_edit` were already public and `engine` has no `wgpu`/`egui`, so what was
  missing was a surface, not a layer: nothing outside the process could reach the commands.
- `CommandRegistry::specs()` is one static slice of specs; a spec carried an id, a label, an
  `enabled` check, a `run` and an optional `Creation`, but `Creation` and its `Level` were reachable
  only inside the engine crate. `CommandSpec::creation_level` is the one accessor the CLI needed.
- `Session::dispatch_in(scope, …)` merges every command dispatched in one `EditScope` into a single
  undo entry. Measured by a test that dispatches a three-line recipe and asserts one `undo()`
  restores the document and `can_undo()` is then false.
- **A part cannot be created without an open product** (ADR 0098): the first recipe test failed with
  `CreationRefused { refusal: NoProductOpen }`. Opening a product is session state and not a command
  (ADR 0029), so a headless run must be told: `run --product <id>`, and a scene with exactly one
  product opens it by itself, because one product is no guess.
- The log sink writes to **stderr** (`app/src/logging.rs`), so a report on stdout stays
  machine-readable; `export` already relied on that.
- `Project::niche` takes a `Contact` adapter; `scene_build::contact_engine()` is reachable from the
  shell, so the CLI measures a void exactly as the viewport does, splayed post and holed plate included.
- `parts` is `OrderPackage::build` → the `parts` table. On the golden scene a shelf row reads
  `length_um: 700000, measured_width_um: 502000` — a 500 mm panel plus its band — so the report
  prints the package's own number and never a second derivation of it.
- `SceneFile` keeps the top-level sections this build does not understand (`extra`), so a recipe
  write has to carry them back or a save in this build would drop a newer build's section.
## Decisions

- Three subcommands behind the existing `cli::parse`/`run`, not a daemon and not a second binary:
  `app/src/cli/commands.rs`, `recipe.rs` and `query.rs`, so `main` still performs the job before
  eframe creates a surface and there is one headless door.
- A recipe is JSON Lines with `{command, params}` and refuses any other key: a misspelt `param`
  would otherwise dispatch the command with no parameters at all and report a confusing refusal.
- All or nothing: one session, one edit scope, one write. A failing line prints
  `line N `id`: <the command's own sentence>` and nothing is written, because a half-applied recipe
  is a scene nobody asked for.
- `--out` absent rewrites the scene read, atomically, carrying its preserved sections back.
  `--dry-run` dispatches everything and writes nothing.
- `query` reuses the derivation that already owns each answer instead of walking the document a
  second way: the node walk for `tree`, the published table for `parts`,
  `Session::panel_diagnostics` for `diagnostics` with stable English codes (`no_material`, …), the
  authored envelope and world origin for `box`, and `Project::niche` for `niche`.
- `Cell::json` joins `export` and its own JSON Lines writer now reads a cell through it, so a report
  row and a package record cannot disagree about what a cell is.
- The report envelope names the query, the file and the revision it read: a stored answer must be
  able to say what it is about. Lengths are whole micrometres; a world coordinate is millimetres
  under a `_mm` key, because a placement is a float at the geometry boundary.
- ADR 0183 records the surface.
## Ruled out

- **A parameter schema in `commands --json`.** The entry's shape asked for "the shape of its
  parameters"; the specs have none, and 51 typed structs would need a hand-written field table each,
  which no test can check against the struct it describes. The report prints the id, the label and
  `creates`; the gap stays in `plan/debt.md` and closes with a real schema. A caller writes the
  parameters from the command's own source and reads the command's own refusal.
- **Reading the field names out of serde's `missing field` error.** It answers the first field of an
  empty object and stops at the first type error, so it would be a fragile reflection trick standing
  in for a schema.
- **A `session.open_product` recipe step.** Opening a product is view state (ADR 0029) and would put
  a non-document command in the registry. `--product` plus the single-product rule is the honest
  shape, and it keeps the registry about the document.
- **One write per step**, so a long recipe survives a failure: that would make a recipe several undo
  entries and a partly written file.
- **A `query` that opens anything.** A report reads the document and the catalogue and writes
  neither, so it is safe to run while an editor holds the same scene open.
