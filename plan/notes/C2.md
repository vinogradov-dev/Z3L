# C2 — the sketch tools place their points from numbers at the cursor

every sketch tool places its point from numbers at the cursor

## What was measured

- `apps/furnicraft/src/draw_gizmo.rs` painted one `size_label` string (`paint_size`, a fixed dark
  plate) and had no field, no focus and no key path apart from Tab → `toggle_drawing_arc_mode` in
  `document.rs`'s `handle_keys` and Enter/Escape → `drawing_key`.
- The atom C1 landed (`crates/ui/src/point_fields.rs`) already owned the grammar: `FieldSet` keeps one
  `FieldRow` per parameter with its own screen anchor, `locked` per row, one focus index, the two
  `FOCUS_REQUESTS` frames and the Escape→release / Escape→cancel ladder. It draws each plate as its
  own `Area` on `Order::Middle`.
- `FieldSet::rect()` was the *union* of the plates. Hit-testing the union against the pointer made the
  plates vanish under the pointer whenever it sat between two plates (the union covers the gap), and
  the vanish made them reappear: a visible flicker, measured in the headless frame test.
- `document.rs`'s `else { self.draw_gizmo.reset(); }` ran whenever `drawing` was false, which includes
  a pointer resting on a panel or on a plate. `reset()` cleared the frozen work plane, the hover and
  (new) the plates, so a plate could never be clicked: the click made `drawing` false and the plate
  disappeared before the press landed.
- `Scrub`'s typed text selects all when the field gains focus. The selection is a `TextEditState`
  char range, not part of the text, so when the shown number moved underneath a focused, unedited
  field the text was replaced and the old selection kept: typing `600` into a plate showing `1331.8`
  produced `600331.8`. The fixed point is in `Scrub`, not in the caller.
- A plate created on the frame after a click shows the live value at the *anchor* (a segment of zero
  length), so the field's first shown value is `0` and it gains the keyboard with that text. That is
  the frame the stale selection came from.
- `DraftMenu` must be its own area: `ViewportMenu`/`node_actions` answers "what the node under the
  pointer owns", and a running draft names no node. `HOST_OWNERS` in `xtask/src/ui_rules.rs` gained a
  row for it.

## Decisions

- The geometry of a placed point lives in `crates/ui/src/draw_fields.rs`, not in the shell: the stage
  each tool's next point takes (`PointState::live`), the point the locks place
  (`PointState::placed`), the four-quadrant smaller angle and the plate anchors. The shell only maps
  work-plane points to the screen and hands `FieldRow`s to `FieldSet`.
- Per tool: the first point is X and Y; line, polyline, arc chord, three-point circle and the
  directed rectangle's direction take length and angle; the arc's chord is measured from the arc's
  **start**, not from the point it passes through, which is what lets the construction line be the
  chord; rectangles take width and height on the outer midpoints of their own sides (turned for the
  directed rectangle); a circle takes a radius on the radius line; a polygon takes a radius and a
  plain 0..360 `Rotation`.
- `ArcFromCenter`'s third point takes only the angle: its radius was fixed by the start point, so a
  `Length` plate there would promise something the tool does not read.
- A typed angle is a direction from `+X` (0..360), and the plate keeps the typed number; the guide
  reduces it to the nearer X end and the short sweep. ADR 0128 records the rule; the four-quadrant
  table is its test.
- The plates are drawn by `show_fields`, called in the paint phase whenever a draft is live, not by
  `update`: a press on a plate makes `drawing` false for that frame, and a plate drawn only while the
  pointer is off-chrome could never be clicked. The plates are part of the chrome hit test per plate
  (`FieldSet::contains`), never by their union.
- Enter/Space ordering: `FieldSet::show` consumes Tab/Enter/Escape while it holds the keyboard and
  `handle_keys` stands aside (`DrawGizmo::holds_keys`, `text_edit_focused`); after an Escape release
  the atom asks for no focus, so the second Escape is the tool's. Escape drops **every** lock, not
  the focused plate's (C1's atom only looked at the focused row).
- `DrawAction::Cancel` is the shell's answer to the atom's cancel, so one path (`apply_draw_action`)
  runs the click, Enter, Close and Cancel consequences.
- The polyline's right-click menu offers straight / arc / finish. Tab is gone from the polyline; the
  fixed tools keep right-click = finish.
- The status bar's finish button now says *Finish the drawing* instead of *Finish (Enter)*, and the
  polyline strip label and `DrawHint` name RMB and Tab's new job.

## Ruled out

- Widening `ToolCard`/`ToolParam` (ADR 0119) for sketch numbers: one plate at one anchor cannot show a
  length on a segment and an angle on an arc, and the box/card parameters are not sketch parameters.
- A second key path in `update`: Enter arrives after the frame's interaction phase, so the placement
  it asks for is applied in the paint phase through `show_fields`, one release path.
- Keeping `reset()` in the `else` of `drawing`: it unfroze the work plane whenever the pointer crossed
  a panel, which was an older defect the plates made visible.
- Drawing the angle as a dimension: still a guide and a number (ADR 0118).
- A checkmark glyph for the current segment kind: the row is drawn disabled with its sentence, which
  is the wording the node menu already uses for an entry that cannot run.

## Measured after the plan was filed

- A live look at the plates was not taken; the look is asserted through the theme inks (ADR 0111,
  0127) and the frame tests. The plate is `theme::floating` at 96 % with `theme::line` and the type
  scale, the same frame as the armed tool's card.
