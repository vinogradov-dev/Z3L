# J25 — what the provider surface rests on, measured before the first edit

## What was measured

- **The gateway has two real wires and two tiers.** `https://opencode.ai/inference/<family>/v1`
  serves `openai` (`POST …/chat/completions` → 401 auth) and `anthropic` (`POST …/messages` → 401
  auth); each path under the other family is 404, so the family segment is a protocol, not an alias.
  A `go` segment between `inference` and the family selects a tier: `…/inference/go/openai/v1`.
- **`GET {base}/models` answers without a key** and carries the model list: 105 ids on
  `/inference/openai/v1` (and the same 105 on `/inference/anthropic/v1`), 36 on the `go` tier of
  either family. The two families answer different envelopes — OpenAI `{"object":"list","data":[{id,
  …}]}` and Anthropic `{"data":[{type:"model",id,display_name,created_at}]}` — but `data[].id` reads
  the same in both, so one parser serves either.
- **Every family serves every model.** The 105 ids of the `openai` family and of the `anthropic`
  family are the same set, so a `claude-*` model is reachable today through the OpenAI wire and needs
  no family routing to answer.
- **The owner's endpoint is the go tier of the openai family** (`…/inference/go/openai/v1`,
  `deepseek-v4.1-flash`, measured in `~/.config/z3l/settings.json`). No key is on this machine (no
  `agent-key`, no `Z3L_AGENT_KEY`), so nothing authenticated could be probed: the 401s and the model
  lists are anonymous reads.
- **ADR 0231 is taken** (`the list is short rows…`), so the task's `Shape:` names an ADR number that
  exists with another subject: the amending record is 0235.
- The settings page has one free-text address and one free-text model; the shell builds
  `mcp::Endpoint` from them in `apply_assistant` and hands it to every tab (J24). `ureq` lives in
  `mcp` only, and `ui` may not depend on `mcp`, so a model list cannot be fetched by the page.
- `testkit::stub_endpoint` / `stub_endpoint_status` already answer a canned body and keep the
  request, so the list request has a harness with no network.

## What this means

The half that is ready: presets, a model list and a picker. The half the `Done:` clause names —
"an OpenCode Go model reaches its family's wire" — needs a second wire (Anthropic `messages`,
content blocks, `tool_use`/`tool_result`) because the family is a protocol and not a path alias, and
no key is on this machine to prove a real turn through it.

## The question for the owner

Which is J25? A — presets and the picker, one wire: the family segment stays `openai`, which serves
every model; the clause is read as "the preset addresses the right tier and path". B — A plus the
Anthropic wire, chosen by the model name, proven against the stub only.
## What was built

- `mcp::openai::models` (`GET {base}/models`, both envelopes) plus `go_gateway` (public, so the
  page's table and the wire's predicate are asserted against each other in `app`, the only crate that
  sees both) and `Endpoint::models_url`. The key travels only when one of its homes holds one; a Go
  tier is sent its session header here too. `testkit` now keeps the request path and reads a
  body-less `GET` as `Null`, so a listing has the harness a completion has.
- `ui::settings`: `PRESETS` (six rows, name + base URL), `Preset`, `ModelRow`, `ListedModels`,
  `AssistantSettings::preset()` derived from the field, `SettingsOutcome::list_models`, and the
  *Assistant* page: a provider combo that writes the address, a *List models* button beside the model
  field, the picker of what the endpoint listed, and the note (asking / none / the wire's refusal).
  The address and model fields stay typed by hand.
- `app/src/model_list.rs`: one listing in flight, on a worker thread, polled per frame; the page is
  handed `ListedModels` and never waits.
- ADR 0235, its README row and two `references/surfaces.md` rows; seven new `text` messages.

## Tests

`mcp`: the list is asked at `/v1/models`, both envelopes are read in the endpoint's order, a row with
no id is not a model, a 401 keeps the provider's sentence, an empty list is an answer, and the Go
tier carries its header on the listing too. `ui`: the assistant section serialises to exactly five
fields (no header, no key), every preset is an address the page accepts and `preset()` reads the
field. `app`: the Go preset is the address `go_gateway` routes on and every preset builds one
`/chat/completions`; a frame test fills the address from the combo and keeps a typed one; a frame
test chooses a listed model; a frame test drives the button to a refused port and reads the sentence.

## Ruled out

- A second wire (Anthropic `/messages`) now: measured unnecessary for every listed model, no key on
  this machine to prove it, and it is a body shape of its own.
- Remembering the chosen preset in the settings file: the row is derived from the field, so the two
  cannot disagree.
- Fetching the list per frame or on opening the page: the request is the person's button, because a
  frame must never wait and an unasked request is traffic nobody wanted.
