# N37 — the fill is a command, not only the window's gesture

## What was measured (2026-11-22)

- The three cells are `ToolKind::Fill` (`crates/ui/src/toolbars/spec.rs:946-980`). Picking one
  arms a gesture (`Editor::arm_fill`, `crates/ui/src/editor/fill.rs:47`); it holds the class, the
  class's fill pair and the mode, and nothing else.
- The shell measures the void through the one niche atom (`ui::Void`) and plans the part with
  `fill_gizmo::plan_at` (`app/src/fill_gizmo.rs:296`) → `Project::fill_plan_in`
  (`crates/model/src/project/fill.rs:201`). The click then builds a `PanelCreate` by hand
  (`app/src/document.rs:2237` `create_fill` → `ui::Editor::create_panel_sized`) and dispatches
  `panel.create`. So the arithmetic the bug names lives in the shell, twice: the plan and the
  command's parameters.
- `FillRequest` (`crates/model/src/project/fill.rs:71`) is already the whole ask: point, fill pair,
  mode, thickness, and the free-axis place the hand carried (`free`). `FillPlan` is exactly what
  `panel.create` stores.
- The material is the catalogue's first board and the name is the class's label in the person's
  language, both chosen by the shell today (`crates/ui/src/editor/creation.rs:121-159`).
- ADR 0098 puts the product guard in the command: `Creation::new(Level::Part, parent_of)` reads the
  parent out of the parameters and compares it with the session's open product
  (`crates/engine/src/commands.rs:201`). A command whose parameters name no parent skips the guard,
  so the fill has to name the product it fills.
- `Sight` is session view state handed to a query (ADR 0175). A command's `run` receives
  `&mut Project, &Directory, params, &dyn Contact` only (`crates/engine/src/commands.rs:219`), so
  the command measures with `Sight::none()`, exactly as `query niche` does
  (`crates/engine/src/read.rs:350`).
- A dry run already exists at the session level (`BatchOptions::dry_run`, `Session::batch`): the
  steps run on a trial copy, the answer names the created id and the echoed parameters, and nothing
  lands. `CommandOutcome` carries a created id or machining id and nothing else
  (`crates/engine/src/commands.rs:24`).

## Shape proposed for approval

`panel.fill` params: `parent`, `at` (world millimetres, the query's own spelling), `class`,
`mode` (`FillMode` gains serde and a schema), `free` (millimetres along the free axis, optional)
and `name` (optional; the class label when absent). It measures the niche with
`Project::niche(at, Sight::none(), contact)`, refuses unless `niche.product == parent` (ADR 0098),
reads the board and its thickness from the catalogue, calls `fill_plan_in`, and writes the panel
through the same model call `panel.create` uses — one revision, one undo entry. The shell's click
dispatches it with the ghost's own point, free place and localized name, so the gesture still writes
the part it painted.

## Open for the owner

1. The product in the parameters (above) — the guard needs it, the task's Shape lists only the point,
   the class and the mode.
2. The sight: with a hidden part in the void, the ghost measures through the person's sight and the
   command through `Sight::none`, so the click can differ from the ghost. Accept and file in debt, or
   carry the hidden ids in the parameters (view state in a command).
3. The dry run: the session's own (created id + echoed parameters, nothing written) or a payload on
   `CommandOutcome` carrying the plan, which makes the outcome non-`Copy` for every command.
## What the owner ruled, 2026-11-22

- The niche tool exists to read a void's parameters; a person gives the point with the cursor and a
  program passes x, y and z. An agent rarely needs it: it knows every size and place and computes
  the panels itself, exactly as a K3-Mebel macro described every detail. The fill is for the case a
  caller cannot compute an irregular cell.
- **A program may write a panel into a closed piece, or with no piece at all.** What matters is that
  the part is not an orphan and sits in the piece's group. The open product is the *person's* choice,
  so the guard moved from the command to the interface (ADR 0226): `Session::run` no longer asks
  `Creation`; `enabled` and `Editor::create_panel_sized` do.
- When an agent works in a scene of several closed pieces it never guesses: it works in the open one
  or in the piece the task names, and asks the person to open it when it is unsure. The explicit
  `parent` of `panel.create` and `panel.fill` is what makes that possible; `engine::guide()` states
  the rule and `open_product` is in every batch answer.
- Hidden parts are a person's sight, not a program's: an agent builds what it knows, so the command
  measures every part in the way.

## What was decided, and what was ruled out

- `panel.fill` params: `parent`, `at` (world millimetres, the query's own spelling), `class`,
  `mode` (`FillMode` gained serde and a schema), `free` and `name` optional. The board and its
  thickness are the catalogue's first, as they are for every created panel; the name defaults to the
  class's English word, made unique. It measures with `Project::niche` (`Sight::none`), plans with
  `fill_plan_in`, and writes through `create_panel` — the one path `panel.create` uses, so one
  revision and one undo entry.
- The three ribbon cells keep their gesture and still write their ghost through `panel.create`:
  the ghost is planned through the person's sight, and routing the click through `panel.fill` would
  create a part the ghost had not shown when a hidden part stands in the void. The trade is written
  in `plan/debt.md`. The two paths still read one measurement and one plan.
- Ruled out: the hidden ids in the command's parameters (view state in a write); a plan payload on
  `CommandOutcome` so a dry run could answer the geometry (it makes the outcome non-`Copy` for every
  command); the ribbon switching to `panel.fill` today (the sight above).
- The dry run is the session's own: the step runs on a trial copy and the answer names the created id
  and the echoed parameters, and the test asserts the planned part is the one the same step then
  writes.
- `command_list` lost its `enabled`/`reason` column with the session-level gate: a discovery
  surface that says "no" about a request the engine accepts is worse than no column.
- The refusal a point with no niche earns is the query's own sentence: `read::no_niche_sentence`
  serves `QueryError` and `CommandError::NoNiche`, and `FillRefusal::sentence` serves the ghost, the
  command and `CommandError::FillRefused`.
