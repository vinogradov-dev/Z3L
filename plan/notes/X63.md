# X63 — a created node takes a number no sibling carries

## What was measured

- `crates/ui/src/editor/creation.rs` named every created node after its kind and nothing else:
  `primitive.kind().label()` returned the bare `"Sphere"` (`crates/model/src/primitive.rs`), the
  camera and the light took the literals `"Camera"` and `"Light"`, the assembly `"Assembly"`, and a
  panel took the tool's own word (`Message::ToolPanel`, the class label, or the fill's label). Five
  spheres created in a row were five siblings called `Sphere`.
- The tree row, the inspector's card, the status bar and the undo history all draw
  `Node::name()`, so one duplicate name made every one of those surfaces ambiguous at once; the
  tree has no second column and the document has no display-only suffix mechanism.
- Nothing in `model` enforced or measured sibling-name uniqueness: `add_object`, `add_panel`,
  `add_camera` and `add_light` store whatever string the command was given, and a rename stores the
  user's words as they are.

## Decisions

- One document query, `Project::unique_child_name(parent, base)` (`crates/model/src/project/query.rs`),
  returns `base`, else `base 2`, `base 3`, …: the first free name among the parent's current
  children. It reads and never writes, so a stored name is never rewritten behind the user's back
  and a number a rename or a delete freed is used again — the names describe the tree, not a
  counter that keeps growing.
- The search is bounded by the number of children: with `k` children at most `k` names are taken, so
  the first `k + 2` numbers always contain a free one, and a hostile document cannot make it loop.
- The creation paths ask it for the default name they already build (`Editor::free_name` in
  `creation.rs`: primitive, panel, camera, light, assembly, product). A name the user types — the
  card's rename, a command's own `name` parameter — is theirs and stays untouched, which is why the
  rule lives in the editor that invents a default and not in the command that stores one.
- Names remain data: the tree, the card and the history read the same string, and no surface grows
  a display-only suffix that a second surface could disagree with.

## Ruled out

- A display-only ordinal in the tree row ("Sphere (2)"): the card, the status bar and the undo
  history would keep showing the ambiguous name, and a second naming rule would exist beside the
  stored one.
- The node `Id` as the visible name or as a second column: ids are labels the document allocates and
  never reuse, not words a maker searches for; a number in the name is readable and survives a save.
- Uniqueness enforced inside the creation commands: a command's `name` parameter is the user's (or a
  script's) own word, and a silent rename there would make "the name I asked for" untrue. The
  default is the editor's business.
- Rewriting existing duplicates on load: a document's names are the user's data, and a load that
  renames nodes is a silent edit (ADR 0096).
