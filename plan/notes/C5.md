# C5 — three ways to build a regular polygon and a rectangle on an angled base edge

three ways to build a regular polygon and a rectangle on an angled base edge

## What was measured

- The polygon cell declared `sketch.create.polygon.edge` with `run: None` and one construction, so a
  method the map promised ran nothing; the cell's main face was captioned «By side count».
- `Path::regular_polygon(center, rim, sides)` takes the rim *point*: radius and phase together. Every
  other construction of the same polygon is therefore a conversion of that point, which C1 measured as
  "no model change" — and the draft is the layer that holds the f64 before a point exists.
- `FieldParam::Sides` was in the atom, in the model's range (3..=128) and in `FieldSet::range`, and no
  tool read it: the count reached the draft only from `Editor::polygon_sides`, which is the ribbon's
  default 6 and has no surface at all.
- `DrawDraft` already kept the count (`with_sides` clamps it), so the plate had one slot to write: the
  draft's own number, not the point being placed.
- `DrawTool::RectangleFromCenterDirected`'s second stage was `Shape::Segment`, so it showed an `L`
  plate whose value `rectangle_from_center_directed` never reads — it takes the axis *direction* only.
  A typed length moved a construction marker and changed no side.
- A rectangle on a base edge cannot be built from `rectangle_from_center_directed` without moving all
  four corners: the constructor recomputes them from the centre and both half extents, and rounds.
- `assets/icons/contour` drew the two shapes with `#58C8DC` contours and `#B8C2CE` control points; a
  control point is a radius-2 dot with a real 1.15 break, so two dots on one edge need 6.3 units of
  clearance and a 7.4-unit side shows 1.1 of itself.

## Decisions

- The circumscribed method reads the apothem straight off the click and hands the model the rim point
  `apothem / cos(pi/n)`, half a step counter-clockwise of the clicked side. `FieldParam::Apothem` is a
  plate of its own (symbol `a`, mm): the number is not a radius, and a radius plate that showed a
  distance to a side would lie.
- The polygon by an edge takes two of its corners and builds the ring **counter-clockwise from the
  clicked corner**, so the board lies on the left of the edge the pointer dragged. Two clicks cannot
  name a side of a line, and the counter-clockwise rule is the one every rectangle in the model already
  keeps; sweeping the edge the other way, or dragging the second click across the first, flips the
  figure and the phantom shows it before the click.
- The side count is a number of the *figure*: it is carried by `Stage`, so all three methods show it on
  the stage that shapes the ring, and its plate writes the draft (`Editor::set_drawing_sides`). A typed
  8 previews and commits an octagon; a released plate (a typed 0) leaves the draft's count alone.
- `DrawTool::RectangleTilted` takes a corner, a base edge and a height; the edge is the width already,
  so the third stage is one `H` plate measured square to the edge on the pointer's side, with the edge
  as its construction line (the rule C4 gave the arc's chord).
- `Path::rectangle_from_edge(corner, end, side)` keeps the clicked edge exact and refuses a zero edge
  or a height on the edge's own line, like every other degenerate rectangle.
- `RectangleFromCenterDirected` moves onto the same rule: `Shape::Direction` shows the angle and no
  length, because a length is a number its figure does not read.
- Both new polygon methods and the tilted rectangle carry no key: the cell's key runs the pinned
  method and the list reaches the rest, exactly as C4 settled for the circle and the arc.
- The polygon's main face is captioned «By radius» / «По радиусу» — the number it takes — instead of
  «By side count», which now describes all three methods.
- Three icons: a hexagon whose dot sits on a side with the apothem stub above it (circumscribed), a
  hexagon whose two corner dots mark one edge, and a tilted rectangle standing on a two-dot base edge
  with the height square to it.

## Ruled out

- A third `DrawTool::RegularPolygonApothem`-style flag on one tool: `points()`, `is_closed()` and the
  field stage differ per method, and every existing method is already a tool of its own.
- Storing the construction method on the polygon: the result is the same ring, and a presentation
  parameter is a schema bump (C1).
- Building the circumscribed or edge polygon in the model as a second constructor: the rim point is
  one conversion, the model already owns the ring, and a second constructor would have to duplicate
  its rounding and its range checks.
- A clamp of a typed count inside the plate: the plate's range and `with_sides`' clamp are the same
  model range, and a clamp in the widget would hide the refusal a bad file should produce.
- A third click on the polygon by edge to name the polygon's side (the pattern `arc_from_chord` uses):
  the figure would then need a click with no number of its own, and the winding rule already answers.
- Keeping the `L` plate on the directed rectangle's axis stage "for symmetry": measured as a number
  that moves a marker and no side, which is the defect the task was filed for.
- A second icon for the rectangle's third method showing three dots: at 26 px the third dot reads as
  another corner, and the height is what the third click names — a perpendicular line says it better.

## Measured after the plan was filed

- No live run was taken. The plates, the stages and the three figures are asserted headlessly: two
  `draw_fields` tests per method, a draft test that builds one hexagon three ways and compares the
  vertices to 2 µm, and four frame tests that type every number — a typed apothem whose ring bounds
  read `apothem / cos(pi/6)`, a typed edge whose first side is the clicked one, a typed height square
  to a 30° edge, and a typed count that commits eight sides.
- The three icons were looked at: `crates/ui` writes them to `target/ui-shots` with the offscreen
  rasteriser at 120 px over a dark card, and the three read apart — the dot on the side, the two dots
  on one side, the perpendicular height on a two-dot base edge.
