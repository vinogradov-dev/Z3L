Total ~31 minutes · 2 dead ends (3 min) · 2 red runs, both mine · 1 `ci` run, green · 0 refused writes.

## What was measured

- `close` wrote `## Next` only in two of four cases (`--next` given, or the order ends), so four closes in
  the reviewed period were refused on a paragraph the tool could have written itself.
- `start` refused any task outside `## Now`, so an empty order took `take` then `start`; three sessions
  in the reviewed period typed both, and `take` alone left `state=idle`, which the gate reports.
- `step` could tick and add a step and nothing else, while `set --field now` writes the backlog entry:
  a running session could not keep its own `resume:` true (the `[plan]` debt entry, cost U89 a minute).
- `set_field` accepted any label, so `--field now` wrote a line that `label_of` cannot see and no later
  `set` can remove (the second `[plan]` debt entry).
- `budget_violations` printed the count and the budget but not `PROSE_WIDTH`, the cause of every
  growing candidate: U88 spent 7 minutes and four attempts on exactly that silence.

## Decisions

- **`close` writes the `## Next` paragraph in every case**, with the sentence `task take` already uses
  for an empty slot, and with `{NOTHING_SCHEDULED}: ` in front of the owner's `--next` when the order
  ends. The paragraph is the tool's to keep true; `--next` only supplies words.
- **`start` takes the head of `## Next` only while `## Now` is empty.** A task behind an open one is
  still `take`'s business, and the refusal names `task take <ID> --at top`: starting it would jump a
  work order that has a head, and an order with two heads is how `STATE:` and the plan disagree.
- **`task step --now|--run|--resume` rewrites the session field** rather than `task start --reset`: the
  session is alive and its note belongs to it, and `start` is the verb of the first minute of a task.
  A field is one line, and a two-line body is refused.
- **`set_field` refuses a label the entry format does not have.** The alternative — deleting an unknown
  label on an empty body — leaves the invented line in the file until somebody asks to remove it.
- **The budget refusal names the width beside the count.** The tool already knew all three numbers; the
  session knew one of them for seven minutes.

## Ruled out

- **A `--dry-run` that prints the candidate's line count.** The refusal already prints the candidate's
  count and the budget, and after this change the width too; a second preview path would be a second
  place to keep in step with `set_section`.
- **`start` taking any open entry, from `## Bugs` included.** A defect can be started, but moving it
  into the order is a decision about the order, which is `take --at top` and the owner's call.
- **Making `take` imply `start`.** The two verbs answer different questions — "does this belong in the
  order" and "is this the work" — and a session that takes three tasks in advance needs the first
  without the second.
- **A sixth phase or a new option on `step`.** The three fields are the whole of what a dead session
  needs to resume; anything more belongs in the note.

## The cheap path

The fixtures cost three minutes of the thirty-one: every verb test rebuilds a plan by string
replacement, and two replacements landed in the wrong order. A `plan_text!(state=doing, now=[P6],
next=[S14])` helper in the test module would have made both a one-line edit — and the same helper
would serve the next handler that has to test what a plan looks like in the middle of a write.

## For the strategy

The refusals were all of one shape: the tool compared numbers or knew the sentence, and printed the
result instead of the cause. Every verb here already computed what the session had to guess. That is
the cheapest class of fix in the tree — no new rule, no new file, no new decision — and it is
invisible to a review that only counts minutes, because the minutes it saves are the ones nobody
spends.
