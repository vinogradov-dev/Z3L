# J9 — the inspector's seven findings, measured before the first edit

## What was measured

- **No workshop profile exists anywhere.** `ui::settings::Settings`
  (`crates/ui/src/settings.rs:647`) holds appearance, viewport, gizmo, snaps, pointer, recent,
  ribbon, panels and assistant — no thickness, gap, sheet or rail height. `catalog` holds a board's
  stock sheet (`BoardView.sheet`, `crates/catalog/src/view.rs:36`) and nothing about the shop's
  rules. `crates/project` carries no settings section. O2 ("a workshop's own numbers live in a file
  the build reads", `plan/BACKLOG.md`) and J12 ("the profile becomes skill cards") are both open, and
  `plan/questions.md` has no entry for the profile's home: its one reference ("the workshop-profile
  question above", line 54) is dangling, which the lost-append story in `plan/debt.md` explains.
  ADR 0191 says "the profile the settings now hold" — today the tree does not hold one.
- **The class registry cannot tell a shelf from a bottom or a top.**
  `docs/domain/classes.md` §6.4 says bottom, top and shelf are one class, `10.11`
  (`ClassCode::HORIZONTAL_PANEL` = 101100), and the node's own name carries the maker's word. The
  wardrobe recipe assigns 101100 to the load-bearing bottom, the overlaid roof and every shelf
  (`app/tests/recipes/wardrobe-800x460x2200.jsonl`).
- **A hanging rail has a class and no creator.** `20.06` (`hanging-rail`, `H` only, host `10.02`,
  `crates/model/src/class.rs:1357`) is registered; no command creates a fitting, and the recipe's
  rail is a plain extruded body with no class. Its host code `10.02` is not a row of the registry.
- **Visibility of an edge is geometric and available.** A rectangular edge's outward direction is
  `RectEdge` (`crates/model/src/panel/geometry.rs:454`: 1 = `-Y`, 2 = `+X`, 3 = `+Y`, 4 = `-X`) in
  the panel's frame; the world placement turns it, and the product frame's front is `+Y`
  (`docs/domain/products.md` §2.1). The recipe bands edge 3 on every carcass board and all four on
  the doors.
- **The overlap derivation already exists and is the one the write refuses.**
  `Project::resting_conflict` (`crates/model/src/project/move_query.rs:407`) and `resting_inside` /
  `nested` (line 700 onwards) already answer "two bodies by volume, a body inside its own shell
  legal", by the contact port's own faces when the adapter is installed. It is private to the drag.
- **The envelope is authored and reachable.** `Container::is_product` and `Project::product_of`
  (`crates/model/src/project/query.rs:351`) find the product above a node; `Envelope::holds`
  (`crates/model/src/container.rs:119`) tests a local point; `Project::bounds_local` gives the
  measured box. Nothing today compares a part with its product's envelope — X116 is that gap, and
  `app/tests/recipes/README.md` names it.
- **`sheet_fit`'s two facts are not both in the document.** A board's stock sheet is the catalogue's
  (`SHEET_LENGTH_SLUG` / `SHEET_WIDTH_SLUG`); grain is not document data (ADR 0216: it is the
  renderer's vocabulary, and the export writes `grain = none`).
- **The tool surface has four coarse tools plus `ui_inspect`.** `crates/mcp/src/tools.rs` declares
  `command_list`, `command_run`, `command_batch`, `query`; ADR 0193 scenario 2 calls `inspect`, and
  ADR 0185 makes it a tool of the same registry. `ui_inspect` reports the window, not the document.
- **The assistant panel exists and can carry a list.** `app/src/chat.rs` draws the conversation, the
  mode switch, the model's checklist and the field; `mcp::chat::Turn` holds the checklist. The
  inspector's panels (`crates/ui`) draw per-node cards, and no card lists document-wide problems.
- **`query diagnostics` is a different thing.** `crates/engine/src/diagnostics.rs` answers panel
  resolution problems (missing material, non-positive core, a cutout outside the core) with no
  severity, no command list and no envelope or overlap rule. The findings are a new pass, not a
  rename of that one.

# J9 — the inspector's seven findings, and what the tree could answer

## What was measured

- **No workshop profile existed**, and the owner made it clear one is not a blocker: the profile is
  the defaults future prototypes seed from (material, drawer, gaps, edge, rail), not the inspector's
  subject. The numbers the seven rules read are now `model::WorkshopProfile` with the record's
  defaults; `Session` holds one, `Session::set_profile` replaces it, and J12/O2 seed it from the
  workspace settings later. The type lives in `model` and not `param` because `ui` depends on
  `model` and not on `param`, and J12's settings section will hold it.
- **The class registry cannot tell a shelf from a bottom or a top**: `10.11` is one row and the
  node's name carries the maker's word (`docs/domain/classes.md` §6.4). The shelf rule therefore
  reads geometry: a `10.11` panel is a shelf when an upright `10.10` meets it at its own height on
  each side of its length. A load-bearing bottom (the uprights stand on it) and an overlaid top (the
  uprights end under it) have no such pair and are not measured.
- **The overlap derivation already existed** as the write's refusal: `resting_conflict`,
  `resting_inside` and `nested` in `move_query.rs`. It is now public as `Project::parts_overlap`,
  so the rule and the refusal are one reading; a body in a shell stays legal, a pair that only
  touches shares nothing, and the contact port measures a body by its own faces.
- **`sheet_fit`'s two facts are not both in the document.** The sheet is the material's catalogue
  stock (`BoardView.sheet`) or the profile's; grain is not document data (ADR 0216), so both quarter
  turns are allowed until it is.
- **A hanging rail cannot be classed in a cabinet today.** `20.06`'s `host` is `10.02`, which is not
  a registry row, so `node.property.set` refuses the class in a `10.01`-family product and the
  recipe's rail is a plain body. The rule reads the class when a scene already carries it (a loaded
  file or a fixture); the host is filed as debt.
- **The tool surface had four coarse tools plus `ui_inspect`.** `inspect` is the fifth, in
  `headless_definitions`, so both the headless server and the attached channel offer it; the CLI
  gained `z3l inspect <scene>` because ADR 0028 asks that an assistant capability also has a door a
  person has.
- **The reference wardrobe recipe reports nothing** with the seven rules as written: run against the
  fixture catalogue, `z3l inspect` answers an empty list, which is the check the recipe's own README
  named as missing (X116).

## Decisions

- **One pass, seven codes, one order**: `engine::inspect::inspect` returns `Finding { code,
  severity, nodes, message, args, suggested_commands }`, ordered by severity then code. The sentence
  is a `Message`, so the wire prints English and the panel prints the interface's language; the
  `suggested_commands` are typed command parameters, and a rule whose fix is a decision (a sheet,
  an overlap) names an empty list.
- **The rules reuse their owners**: the envelope is `Envelope::holds` (the footprint, not a box), the
  overlap is `Project::parts_overlap`, the classes are the registry's traits, the banding is
  `Panel::has_band_on`, the sheet is `catalog::BoardView`, and the profile is the only number a rule
  reads that the document does not carry.
- **A shelf is measured against the free span between its uprights**, target `opening − 2 × gap`,
  error when it is wider than the opening, warning when it is more than `shelf_loose` narrower than
  the target. The ADR's "bearing under 30 mm" is a hardware fact (shelf pins, cleats) and waits for
  M8 with the rest of the hardware findings; it is in `plan/debt.md`.
- **A rail's top is the nearest horizontal part above it**, else the product's ceiling; 40 ± 5 mm is
  the drop, and the 50 mm clearance is measured to a shelf *below* the rail (the part above is the
  top the drop already measures).
- **A front's opening is the product's width** and the pair's outer edges are flush: a pair's gap is
  the workshop's and each front is `(opening − gap) / 2`. The mounting form (overlay or inset) is
  not document data — the hinge class carries it, not the door — so an inset front is measured by
  the overlay reading until the form is stored. A front that shares volume with an upright is an
  error, by the same overlap reading.
- **A visible edge is the one whose outward normal is the product's front (`+Y`)**; every edge of a
  front is visible, and a class that admits no banding (the back) is not inspected.
- **The panel re-reads the rules once per revision**, not per frame, and lists six findings with an
  "and N more" line; the tool answer carries every one. The model explains the list and never
  computes it.
- **The profile is a setting and not document data**: no scene stores it, so the same document in
  another shop is measured by that shop's numbers.

## Ruled out

- **A profile section in `ui::settings` now.** J12 owns it; J9 needed the numbers, not the editor,
  and the type in `model` is what J12 will hold.
- **Seven tools, one per code.** ADR 0191 asks for one list; `inspect` is the fifth coarse tool.
- **A `query` variant.** A question is one read model with one answer; a finding carries severity,
  commands and an order, and ADR 0193 names `inspect` as its own tool.
- **A separate findings panel.** The assistant panel already shows the model's checklist; the rules'
  list is the same kind of derived list, and a new host would be a second place to look.
- **Storing a finding in the document.** It is a derivation; the revision is the only key.
