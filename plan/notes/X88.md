# X88 — the object rotate tool stops where the bodies stop

## What was measured

- The owner's scene (`/home/alx/scene.z3l`, not committed — a scene is the maker's data) holds a cone
  turned into a 190 x 330 x 100 board: the cone's own surface is **1.2 mm inside** the board at its
  corner (board-local ~(93.8, 163.8, 22.6) against the box -95..95 x -165..165 x 0..100), and 15 mm
  clear of the tall panel beside it. The maker says he turned the cone by hand and then carried it to
  the two blocks with the object move.
- **The object move is not the gap.** From a free start (the cone 30 mm out on +Y) the rule cuts the
  pull back at **-27.601 mm** with `Stop::Node { id 2 }` — the board's own face, zero overlap — and the
  write guard accepts that landing. A pair the document already holds inside is only let out, never
  deeper (ADR 0178), so the carry could neither create nor repair the 1.2 mm.
- **The turn is the gap.** `commit_rotation` answers `measured: false` (`app/src/gizmo_math.rs`), so
  `apply_gizmo_commit` writes `unmeasured: true` and `node.placement.set_many` skips
  `resting_conflict` — the turn is the one gesture that can put a body inside another (ADR 0180
  deferred exactly this to X88).
- The box reading is not an alternative: without the adapter the same pull answers **0 mm**, because
  the world box around a turned cone already overlaps the board (X85's coarse reading).

## What X88 has to build

A `Project::rotate_rule` beside `MoveRule`: the destination first, then a bisection of the angle
against the same free-place predicate, reusing `Mover`, `Obstacle` and `Measured`, so the drag, the
release and the write read one measurement. The ring drag asks it per frame; the release commits a
measured turn (`PlacementCommit::measured: true`), and the free rotation keeps `measured: false` as
ADR 0180 has it.
