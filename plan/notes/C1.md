# C1 — the sketch cycle: the point at the cursor, two guide kinds and the latched move

the sketch cycle: the point at the cursor, two guide kinds and the latched move

## What was measured

- The reference is a set of OpenCAD Studio screenshots in the owner's picture library (2026-11-15). The length plate sits on the segment itself, the angle plate outside an arc, and a dashed line runs from the anchor along +X with the same radius as the arc. The arc radius equals the segment's length. The active field is a blue plate; the others are neutral plates with a light border.
- `app/src/draw_gizmo.rs` draws one text label for the live size (`size_label`, `paint_size`) and snaps the pointer to a draft end, the 10 mm grid and the axis. It has no field, no focus and no keyboard.
- `app/src/contour_gizmo.rs` keeps a private `NumericEntry` (text, `focus`, `edited`, `GripValue`, `NUMBER_OFFSET = (18, 12)`) and a private keyboard path for one grip. The grips already accept a length or an angle per grip (`GripNumber` in `crates/ui/src/contour_grips.rs`).
- `crates/ui/src/tool_card.rs` (ADR 0119) is the shared plate at the pointer and the same rows in the inspector; `crates/ui/src/scrub.rs` (ADR 0092) is the shared numeric field with its unit outside the box. Neither is reachable from a drawing tool.
- `crates/ui/src/theme.rs` has one guide ink, `helper` (ADR 0111), one `GUIDE_WIDTH`, and a contrast test that demands 3:1 for a guide. A pale grey line cannot pass it on a light board.
- `crates/ui/src/toolbars/spec.rs` already declares methods that run nothing: `sketch.create.line.angle`, `sketch.create.circle.two-points`, `sketch.create.circle.tangent`, `sketch.create.arc.three-points`, `sketch.create.polygon.edge`. The arc's main face is already the three-point arc but is labelled "Through 2 points".
- `Path::regular_polygon(center, rim, sides)` in `crates/model/src/contour.rs` builds the inscribed polygon from the rim point and the phase; the circumscribed and edge forms are conversions of that rim, so neither needs a model change.
- Tab is the polyline's line/arc switch (ADR 0076) and `handle_keys` owns it; the draft has no context menu.

## Decisions

- Every field carries the live value of the pointer. One field is always focused; Tab hops and a click on a plate focuses it.
- A typed number locks its parameter and outranks a snap; typed numbers are never snapped. `0` returns the parameter to the pointer.
- Enter places the point with every field. For a fixed tool the last point also commits the figure, as a click does today. Escape drops the typed value first and ends the tool second.
- The first point takes X and Y; every later point takes the parameters of its figure. The angle is absolute from +X in the node's local plane: 0..360 may be typed, the smaller angle is shown, `a = φ` for `φ <= 180` and `a = 360 - φ` above it, with the reference axis +X or -X accordingly. A typed `a` sets `φ = a` on the current side and a value above 180 flips the side.
- The reference guide is the +X line from the anchor with the segment's length and an arc of that radius. The construction line is the measured chord. The reference always shows; the construction line shows only for an arc's chord and for a moved node's old position.
- The reference is two thin strokes, light over dark, and the thinnest line in the scene: an exception to ADR 0111's one amber, taken because a single pale ink cannot read on a white board, a dark board and a gradient.
- Length is shown to 0.1 mm, an angle to 0.1 degree, a side count whole. Plates are horizontal at the outer midpoint of their side and never cover the point being placed or the snap marker; they flip at the edge of the workspace.
- A contour node moves in a latched mode: a click selects, a click on a selected node latches the move, the next click drops it with one command and one undo entry, Escape restores. A press-and-drag stays the one-gesture path. Only contour nodes; object placement and the grips keep their grammar.
- A polygon's construction method is not stored. The result is the same regular polygon and the method is a construction parameter, so no schema bump and the inspector keeps reporting the circumradius.
- The new cells are a circle by diameter, an arc from start, end and radius, a circumscribed polygon, a polygon by edge and a rectangle on an angled base edge. Each is a ribbon cell; the draft takes the method as a parameter and the commit stays `object.path.create`, so no command is written per method.
- The polyline keeps per-segment rules; its line/arc switch moves to a right-click menu because Tab belongs to the fields.

## Ruled out

- A second numeric field inside the drawing tool: ADR 0118 names the mechanism, and the contour draft already re-implemented it once; the atom is the fix, not a third copy.
- A pale grey guide ink: it fails the 3:1 rule on a light board; the two-stroke pair is the pointer's own answer (ADR 0121) applied to the thinnest line.
- Storing a polygon's method in the document: a schema bump for a presentation parameter.
- A command per polygon or circle method: the draft carries the method and the commit is the one path command.
- Drawing the angle as a dimension: the arc is a guide, not a document dimension (ADR 0118, 0029).
## Measured after the plan was filed

- `ToolView`/`ToolRow` (crates/ui/src/tool_card.rs) is one plate at one anchor with a closed `ToolParam` (Height, LowGap, HighGap). The sketch numbers cannot use it: a line's length sits on the segment and its angle on the arc, so the point has two plates at two anchors, and the parameter set is a different, larger one. Widening `ToolParam` for them would put the card's keyboard and the inspector's mirror behind sketch parameters they never carry.
- The shared part is `Scrub` (crates/ui/src/scrub.rs): 76 x 22, unit outside, focus through `Scrub::focus`, a typed value through `CommitPolicy`. A sketch plate is one `Scrub` in the card's own frame and radius, at its own anchor.
- The atom therefore owns: a closed `FieldParam` (x, y, length, angle, width, height, radius, diameter, sides, rotation), one `FieldSet` per point stage with an anchor per field, the focus index, the set of typed-and-locked parameters, and a `FieldEvent` of Edit, Tab, Commit or Cancel. The gizmo computes the live values from the pointer every frame and applies the locks back to the point it would place.
- `Scrub`'s drag writes through `Session::edit_scope`; a sketch field must not mint a scope, because the draft writes nothing. The atom draws the field with a commit policy of `Typed` and keeps the number in view state.
Correction to the two bullets above, after reading `scrub.rs`: `CommitPolicy` is `Live` or `OnRelease`, not `Typed`, and the undo scope is minted by the caller through `Scrub::edit(fresh)`, not by the field. The atom therefore calls neither `edit` nor `Session::edit_scope`: the draft is view state, so the field's `FieldOutcome` is read for `commit`, `response` and `error` only, and the atom keeps the typed number itself. Escape and Tab are read by the atom when its plate owns the focus, so the drawing tool keeps one key path.
