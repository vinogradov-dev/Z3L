# X125 — What was measured

## What was measured

- The model asked for the root id, then for the side order, then about micrometres, and returned no
  cube. `object.cuboid.create` takes `parent`; the root id is always available in `Project::root`,
  and the engine's own box test creates a box under it in one dispatch.
- The request held `engine::guide` (static) but no live ids, and the prompt said "ask before you
  guess". The model could not read the tree because nothing sent it.

## What was decided

- `engine::scene_brief` reads the root id, the open product and a bounded node list (80 nodes, 12
  levels, names folded); `Conversation::set_brief` carries it, and `OpenAi::request_body` appends it
  to the system message. The shell replaces it for every message, so it never grows the history.
- The prompt states the convention: millimetres, width × depth × height, convert to micrometres
  silently, a free body belongs under the root, act on the numbers, ask only what neither the brief
  nor the convention answers, and do not correct "cube" to "box".
- The wire is still chat completions; the Go protocol table is a later task.

## What was ruled out

- A new "create a cube" command: `object.cuboid.create` already does it; the missing fact was the id.
- Making the brief a transcript line: it would grow every request; a system note is replaced per
  message.
- Letting the model query the tree over the MCP tools from the endpoint backend: the endpoint backend
  is not an MCP client, and a brief is one cheap read.
