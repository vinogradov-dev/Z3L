# P17 — What a session measured, decided and ruled out.

What a session measured, decided and ruled out.

## Measured

- The plan's one-live-task rule lives in five places, not one: `analyze` (the `[~]` count and the
  session-note rules), `budget_violations`, `check_with` (reads `plan/SESSION.md`), `edit` (writes the
  note), and the writer verbs, which recompute "the head of `## Now`" in `start`, `close`, `take`,
  `defer` and `reopen`. A per-stream plan therefore could not be a gate-only change: every writer that
  names the current task had to learn which stream it was talking about.
- `std::ptr::eq` on a `&Stream` returned by `Streams::owner` compares addresses, and a cloned
  `Stream` never matches. Four verbs silently stopped moving `STATE:` until the check became
  `owner(id).key == stream.key`. Nothing failed to compile; only the plan's own gate caught it.

## Decided

- A stream is a set of phases; a task's phase letter names its stream. The plan does not repeat a
  stream field on every entry, and the backlog cannot drift from the checkout that works it.
- The declaration is one optional line in `STATUS.md` — `STREAMS: agent=J catalog=O prototypes=Q` —
  and `state streams` is the verb that writes it. A plan without the line has one stream and keeps
  every rule, which is why the crate's own tests and `init` still work unchanged.
- `STATE: state=` and `STATE: task=` stay the primary (`app`) stream's. The alternative — a key per
  stream on one line — puts four writers on one line, which is the reason `plan/` has one writer.
- A declared stream's note is `plan/SESSION.<key>.md`; the primary keeps `plan/SESSION.md`, so the
  file every instruction, skill and template already names is still the one a single-checkout plan
  has. `check_with` also lists `plan/SESSION.*.md` and refuses a note whose path names no stream.
- `cargo xtask status` prints one row per stream, and only when the plan declares more than one: a
  single-stream block repeats nothing.

## Ruled out

- Four `[~]` markers with no stream rule: two entries of one checkout would both claim to be in
  progress, and the gate could not tell them from two checkouts working.
- A `SESSION.md` per phase letter: the primary owns every area letter (A–V), so it has no single
  letter to name its note with.
- Teaching the gate about the worktree table in AGENTS.md §6.2: the plan is the source of truth, and
  the stream a task belongs to is already in its id.
