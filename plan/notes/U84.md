# U84 — the method list loses its captions

## What was measured

- `VariantSpec::section` and `Method::section` were the only grouping in the list; 19 match arms in
  `toolbars/spec.rs` declared one, and `ToolSpec::default_method` copied the first variant's caption
  onto the tool's own row so a caption never sat above the row it described.
- The list drew a 16 pt `CAPTION_HEIGHT` band, so the circle's four rows plus two bands were
  34 + 4 x 30 + 2 x 16. Three messages existed only for those bands (`SectionBuild`,
  `SectionTangents`, `SectionFillMethod`).
- `toolbars::tests::a_click_inside_the_list_keeps_it_open` clicked (150, 110), which was the caption
  band above the first row; with the band gone that point is row 0, whose click runs the method and
  closes the list. The test now clicks the header, which is inside the frame and runs nothing.

## Decisions

- A list is `HEADER_HEIGHT + rows x ROW_HEIGHT`; `list::height(rows)` states it once and the drawn
  popup is checked against it plus the frame's `FRAME_STROKE` on each side.
- ADR 0110 named the caption in its decision, so it gains an amendment rather than being left to
  disagree with the code; the fill cell still reads as one panel because it is one cell whose header
  names it and whose two rows name the builds.

## Ruled out

- Keeping the caption for the fill cell alone: the owner asked for one flat list, and a rule with one
  exception is the second line to read that the task removes.
- Grouping by drawing no band but keeping a gap: the rows then no longer share one pitch, and the
  height test (`rows x ROW_HEIGHT`) would be a lie.
