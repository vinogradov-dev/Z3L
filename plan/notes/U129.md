## What was measured

- The slot exists since Y7 and nothing writes it from the window: `model::MaterialRef` is a
  non-zero `u32` (`crates/model/src/ids.rs:93`), `Panel::render_material`/`Object::render_material`
  hold it, and `Project::set_node_material` (`crates/model/src/project/node_cmds.rs:88`) already
  refuses the root, refuses a container (`NodeHasNoMaterial`) and bumps one revision.
- `COMMANDS` counts 71 specs (`crates/engine/src/commands.rs:687`); `node.material.set` is not one
  of them, and `ROWS` in `crates/ui/src/inventory.rs` has no row for it.
- The closest sibling is `node.decor.set` (`crates/engine/src/node_cmds.rs:576`): one optional
  field on a panel or an object, `#[serde(default)]`, one snapshot undo entry. Its row is `Api`
  only (`inventory.rs:681`) and its card is Y17's (ADR 0252), so the material row must leave room
  for it beside itself.
- The inspector composes cards in `crates/ui/src/editor/cards.rs:72`: placement, pivot, then the
  kind card (panel/object/camera/light/container), then the properties card for every node.
- The panel card already has the picker grammar this entry needs:
  `section("panel.material")` -> `ComboBox` over `session.directory().boards()` with a "No material"
  row and a danger label for a record the catalogue lost (`panel_card.rs:388`, `459`–`490`).
- The object card has one reading order and no headers (ADR 0116), so a material section cannot be
  added there; only a bare row can.
- `Session::materials()` hands the `&Library` (`crates/engine/src/session.rs:407`);
  `Library::records()` walks it (`crates/materials/src/library.rs:50`). The `MaterialRef` <->
  `MaterialId` conversion lives in the shell today (`app/src/scene_build.rs:84`).
- The palette lists every spec whose row has any place other than `Api` (`palette.rs:191`) and
  refuses a capability whose parameters cannot be guessed with one message
  (`node.rename` -> `PaletteNeedsNewName`, `messages.rs:992`).
- The ribbon's Scene tab carries a planned "Materials" group with `scene.materials.catalogue` and
  `scene.materials.assign` (`crates/ui/src/toolbars/spec.rs:1069`): no icon, no run, a placeholder
  cell. That cell is not this entry's place.
- `engine::inspect` takes `(project, directory, profile, contact)` (`inspect.rs:196`) and has seven
  codes; the render library is not one of its inputs today.

## Decisions (proposed; the owner approves before the first edit)

- One command `node.material.set` in `node_cmds.rs`: `{ node: Id, material: Option<MaterialRef> }`
  with `#[serde(default)]`, enabled for a panel or an object that is not the root, one revision and
  one snapshot undo entry. A reference the library does not hold is **accepted**, because a scene
  travels between workshops with the numbers it named (ADR 0245).
- The picker is a `ComboBox`, the same atom the panel's catalogue material row uses: a "No
  material" row first (that is the clear), then the library's records by `name()`, and one dim
  sentence when the library is empty (`Message::MaterialsEmpty` exists at `messages.rs:922`).
- The row is one shared function with two call sites: the panel card draws it as a section
  (`panel.surface`) directly after `panel.material`, the object card draws it as a bare row after
  its head. Both are view code; the write is the command.
- The palette lists the id and refuses it with a sentence that names the card, the way
  `node.rename` does.

## Ruled out

- A popup picker shaped like `class_picker`: a `Popup` is a host with its own `HOST_OWNERS` row,
  and the ComboBox beside the catalogue material already reads better in a dense inspector.
- Refusing a `MaterialRef` the library lacks: ADR 0245 makes a missing record a placeholder plus a
  sentence, not a refusal that would drop the number a file carried in.
- A second slot or a per-face list (ADR 0245 holds one slot; per-face composition is O18).
- Filling the slot from the catalogue record in this entry (that is O16's bridge, one line).

## Open questions for the owner

1. Home of the row: both kind cards through one shared row (proposed), or one row in the
   `properties_card` drawn for every node, or the panel card only for now?
2. A record the library lost: the card's danger ink on the row (proposed, and cheap), or an eighth
   `engine::inspect` code `material_missing` — which changes `inspect`'s signature to take the
   library and reaches the report, the MCP `findings` tool and the CLI.
3. The icon: the inventory's `icon` column means "one button draws it", and no surface draws a
   button for this row today (the palette prints text, the cards print no icons). Author
   `assets/icons/actions/material.svg` and draw it as the row's leading glyph, or leave the row
   without artwork, or author it for the ribbon's planned `scene.materials.assign` cell and give
   that cell its own entry?
