# O6 — The directory application, and what a save costs

The directory application, and what a save costs

## What was measured

- `crates/catalog/src/source.rs` is 600 lines of reader: `FolderSource`, `DirectorySource`, the
  revision stamp and the refusals. There was no writer at all, so the folder was a format, not a
  document.
- The write path had two ready-made gates and one missing piece: `RegistryWire::rows()` builds the
  kind and property rows, `Directory::new` decides whether a set of records is a directory, and
  `ItemWire` only went one way (`to_item`). Nothing wrote a record.
- `crates/ui` already depends on `catalog` (layer 7 over layer 2), so the screen could live in `ui`
  without a new crate or a layer-map change.
- `app` has no `lib.rs`: it is one binary root. A second `[[bin]]` therefore cannot reach
  `settings_store::config_dir`, which is the one place the rule "nomenclature/ sits beside
  settings.json" exists.
- `Scrub` is `pub(crate)` in `ui` and works without an `EditScope` (`fresh: Option`), so a
  non-document number field needs no undo machinery.
- `Message::text` returns `&str`, `Length` has `millimetres_f64` but no `as_millimetres`, `Money`
  carries `u64` minor units, `ItemId` implements `Display` as `package-serial`.

## Decisions

- `catalog::FolderWriter`: exclusive `lock` (`create_new`, never a wait, names its pid, removed on
  drop), the candidate directory validated with the loader's own rows before any file is touched, the
  record written to `items/<kind>-<serial>.json` through a temporary sibling, the package manifest
  last. The manifest is what the reader's stamp watches, so "the revision last" is one change a poller
  sees, after every file of the write is in place.
- A record's file name is kind plus serial, never the record's own slug: a rename rewrites one path.
- `ItemWire::from_item` is the reverse of `to_item`, so a file keeps naming properties by slug.
- `ui::DirectoryEditor` holds the folder, the snapshot, the draft and the status; the card's rows come
  from the kind's accepted properties, a length is typed in millimetres and converted to micrometres
  once, in `ValueDraft::to_value`.
- The screen creates no egui host: the shell hands it a `Ui`, so `HOST_OWNERS` gains no row and the
  window skeleton stays one owner.
- `z3l directory [<folder>]` is a mode of the one binary; the second `[[bin]]` the entry's Shape named
  is the next step only after `app` gains a library (`plan/debt.md`, `[design]`).
- The refusal is the status line: `save` writes its own sentence and returns it, so the button and
  Ctrl+S cannot disagree.

## Ruled out

- **A second `[[bin]]` now** — it would duplicate the config-directory rule or hard-code a path.
- **A crate `app-directory`** — a new layer-map row, a new `PROJECT.md` entry and a copy of the eframe
  setup, for one window.
- **`egui::DragValue` for the millimetres** — a second number field against ADR 0092.
- **A modal over the scene** — the editor must not write the directory (ADR 0158), and a modal would
  put a folder's write inside the document's dirty flag and undo stack.
- **Writing the record straight from the card without validating the candidate** — a save and a reload
  would then be able to disagree, and a refused row would break the editor at its next frame
  boundary.
- **A revision counter file** — the folder's revision is a hash of the files a snapshot reads; a
  counter would be a second source of truth that a hand edit silently ignores.
