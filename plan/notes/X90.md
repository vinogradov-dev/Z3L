# X90 — the probe and the frame budget

## What was measured

- A rule over **300 bodies** cost **37–40 ms to build** and **0.63 ms per ask** (dev profile is already
  optimised; release gave the same numbers). `prepare` alone was 22 ms of the build — 74 µs a hull.
  Both numbers are past a frame, so a drag in a real workshop hitched when it started.
- The probe never asked the port at all: `first_face` met `SurfaceBox::face_hit`. A turned *box* is
  already exact there (the box has its own frame), so the port matters only for a body that is not a
  box — a ball, a cone, a plate with a hole.
- Measured against an ordinary scene, the port's ray moved a cell's **plane by rounding** (a panel's
  hull answered 326.903… where the box answered 326.903…, but the free-place reading of the face
  flipped), and `the_fill_ghost_passes_the_board_it_meets_and_holds_at_the_frame_envelope` failed:
  a part stopped following the hand across a board. That is a defect in the **product**, not in the
  test: a cell is where a board is cut.

## What landed

1. `geom::Impact` and `Solid::ray(origin, direction)` — the port casts a ray; `contact-parry` answers
   with `RayCast`, the stub in `geom`'s tests with its own box. Two tests: `a_body_answers_the_face_a_ray_meets`,
   `a_ray_meets_the_bodys_own_face` (a ball, a turned board, a heading of zero length).
2. `Contact::handle() -> Arc<dyn Contact>` — a rule outlives the call that built it and keeps the
   adapter; an adapter is a service, so the handle is a pointer (`Parry` is a unit value).
3. **Lazy obstacles.** `Obstacle` keeps the geometry the shape comes from and an `Rc<OnceLock>`, and
   `Obstacle::body(contact)` builds the shape the first time a pair reaches for it. `rule_of` stores
   `contact: Option<Arc<dyn Contact>>`; `resting_conflict` keeps its borrow and resolves lazily too.
4. **Broad phase.** `blocked_at` skips a pair whose moved box and obstacle box share no volume, and
   `stop_at_contact` skips a pair that does not overlap across the travel axis. A body lies inside its
   box, so both culls are exact.
5. `contact_shape::body_shape(geometry, min, max)` — the shape from a geometry already in hand, so the
   rule builds it without the project.
6. `a_drag_in_a_hall_of_three_hundred_bodies_is_built_at_once_and_measured_where_it_reaches`: the
   build and 120 asks each fit in a frame (16 ms), where an eager build was 40 ms.
7. `probe`/`niche`/`fill_plan` take `Option<&dyn Contact>`, threaded through `ui::Void::measure`,
   `ui::pointer_point`/`pointer_face`/`free_place`, `void_gizmo`, `measure_gizmo`, `fill_gizmo` and
   `document` — every caller hands the session's adapter, so no caller has a reading of its own.

## Ruled out

- **Preparing eagerly but capping the scene.** A drag has no domain: the hand may carry a piece across
  the whole workshop, so no reach bound is sound. Lazy preparation is the only honest answer.
- **`&dyn Contact` inside `MoveRule`.** It puts a lifetime on a value the shell keeps across frames
  (ADR 0179). `Arc` behind `Contact::handle` keeps the rule a plain value.
- **The probe reading the port today.** It moves a cell's plane by rounding, and a cell is cut into
  boards; a defect there is silent. Deferred to X92 with the measurement above, and named in the code.

## Left for X92

The probe measured against a body the boxes cannot describe — a plate with a hole, a notched panel —
with a test that a ray crosses a hole and stops at the face behind it, and a cell built from those
faces. The port's `ray` is ready; what is missing is a reading that does not move an ordinary cell.
