# J13 — the five scenarios, and what running them found

## What was measured

- **The surface had no door to the history.** `Session::undo` was a shell action (`app/src/document.rs`)
  and no command id named it, so ADR 0193's "`undo` restores the document the scenario started from"
  could not be asserted through any tool. `undo` is now a tool of its own on both doors, because a
  command cannot be it: a command is a step of a batch, a batch is one undo entry, and taking an entry
  back from inside the entry is a contradiction. It refuses in `AgentMode::Plan` with the batch's own
  `PLAN_NOTE`, so a caller learns the person's switch once (ADR 0190).
- **`z3l mcp serve` speaks newline-delimited JSON-RPC over its own stdio**, so the client is thirty
  lines of `std::io` and no dependency: `initialize` with `protocolVersion` `2025-06-18`, the
  `notifications/initialized` frame, then `tools/call`. `app` may not depend on `rmcp` (ADR 0186), and
  a hand-written client is also what a foreign client is.
- **A headless client has no message to group calls in.** The chat door passes an `EditScope` and the
  headless door does not (`Door::Headless` has no scope), so "copy it and change the doors" is two
  batches and two undo entries through MCP, while the same two calls in one chat message are one
  entry. The scenario asserts two entries and says so; the scope stays the shell's answer and never a
  request field (J11, ADR 0230).
- **Scenario 5 cannot land today.** `product.create` puts a product in the root or a plain group, and
  nothing reparents an authored piece, so moving the wardrobe into the niche's box is refused:
  "`Распашной шкаф 800×460×2200` would come to rest inside `Ниша`". The scenario therefore asserts the
  refusal sentence (which names both), that the refused batch wrote nothing, and that the piece is
  2200 against the niche's 2140 — the arithmetic a person has to hear. What would make it land is
  either a reparent command or a "put this piece in that frame" operation, and both are the owner's
  call: `plan/debt.md` carries the measurement.
- The recipe's own numbers held through the surface: 38 steps, 14 panels, the sizes of
  `app/tests/recipes/README.md`, revision 53 after the build — the same document the command line
  writes. The 900 mm turn composed from the tree's names lands with no refusal and no finding.

## What the test is

`app/tests/scenarios.rs`, one binary, five scenarios, each starting its own `z3l mcp serve` on a
workshop the test owns (settings, catalogue and scene in a scratch folder). Every scenario asserts
the four things ADR 0193 names: the task completed, one undo entry per turn, the count of mutating
calls, and a refusal the next call can act on. It reads nothing from this repository at run time
except the fixtures, and it never touches the `Project`.

## What a next session should know

- `undo` is in `crates/mcp/src/tools.rs` (`TOOL_UNDO`, `UndoRequest`), `crates/mcp/src/server.rs`
  (`undo`), `crates/mcp/src/channel.rs` (`Call::Undo`) and answered by the window in
  `app/src/main.rs::answer_channel`.
- The scenarios are slow by design (a process and a real build each) and run with
  `cargo test --workspace`; run one with `cargo test -p app --test scenarios <name>`.
- Not asserted, because the surface has no door: `render_preview` (ADR 0193 asks for it "once it
  exists" and it does — a scenario that looks at the picture is a later turn), and a real model.
- The niche gap is measured, not designed: `plan/debt.md` `[engine]` holds it.
