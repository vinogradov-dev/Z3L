# U118 — the five shading styles are one band, and each split owns its glyph

## What was measured

- `app/src/view_cluster.rs::style_buttons` drew the five styles as five `tool_button_labelled`
  cells straight into the wrapped row: `horizontal_wrapped`'s default item spacing plus one button
  cell per style, so the run read as five switches between two dividers.
- `layout_popover` drew the four splits as `egui::Button::new(label)` text rows, and the cluster's
  layout cell drew `view/layout.svg` — one generic two-pane frame — whatever the layout was.
  `view::LAYOUT` had exactly one caller (`view_cluster.rs`, the cell), so it died with the change.
- The decided anatomy is the transform band (`app/src/status_bar.rs::transform_mode_ui`, ADR 0113):
  a `egui::Frame` filled with `theme::control`, `RADIUS` corners, `item_spacing.x = 0.0` and one
  selected cell per state.
- `every_icon_uri_names_its_theme_and_file` pins the declared icon count: 117 → 120 after removing
  `layout` and adding four files.

## Decisions

- The band copies that anatomy verbatim: one tinted frame, five touching cells, the view's own style
  drawn pressed, one divider on either side (they were already there).
- The group names itself through `WidgetInfo::labeled(Role::Group, …, Message::ShadingGroup)` on the
  frame's response, and its hover line is `Message::ShadingGroupHint` on the same response. egui
  keeps one tooltip per layer and the innermost widget wins, so a cell keeps the hint that names its
  own style and the group's sentence answers the frame alone; a screen reader always reads the name.
- Four files under `assets/icons/view/`: `layout-single`, `layout-columns`, `layout-rows`,
  `layout-quad`, drawn on the same 24 grid and ink as the generic `layout` they replace (1.5 frame,
  1.3 divider, 0.14 tone on the first pane). The tone is the passive band, so the raster stays inside
  the 10–40 % coverage the icon test asserts.
- `LayoutKind::icon()` lives beside `LayoutKind::label()` in `app/src/view_layout.rs`, so the cell
  and the popover row read one table instead of two match arms in the cluster.
- `preset_row` became `glyph_row(icon, label, on)` and `preset_row` is a one-line call of it; the
  split rows paint the same glyph-plus-name face the preset rows do.

## Ruled out

- Keeping `layout.svg` for the cell: nothing else draws it once the cell follows the active split,
  and an unused asset is a dead row in the theme table.
- A dim "Shading" caption inside the band: five glyphs plus a word widen the cluster's narrowest
  row, and the transform band names itself by its words alone for the same reason.
- Repeating the group sentence in every cell's tooltip: five tooltips saying the same thing bury the
  label that names the style, which is the one fact a hover there has to carry.

## How it was verified

- Headless, on the band: the frame is driven with `egui::RawInput` and read through `accesskit` — one
  `Role::Group` named *Shading*, five buttons in `ShadingStyle::ALL` order left to right, the cells
  touching, all five inside one control-filled frame, exactly one accent-filled rect at the view's
  style, and a click on the last cell returning `SetStyle(Translucent)`.
- Headless, on the splits: each `LayoutKind` paints a different texture inside the layout cell, and
  each popover row paints its glyph 14 pt left of its name.
- Looked at: the `#[ignore]` interface shots (`target/ui-shots`, dark and light) show the band as one
  block with the pressed cell filled, and the layout cell drawing the single-view frame.
