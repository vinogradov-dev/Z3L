# X107 — a call the window did not reach, and the answer it earned

a call the window did not reach, and the answer it earned

## What was measured

- `app/src/main.rs::answer_channel` refused a dispatch with `mcp::busy()` *before* dispatching, so a
  call refused for a gesture never moved the document. The sentence the X107 measurement read came
  from the other place: `AttachedServer::call_tool`'s `timeout(ANSWER_DEADLINE, …)` —
  `ANSWER_DEADLINE` is 120 s in `crates/mcp/src/channel.rs` — and both answers were the one `SILENT`
  const, so a caller could not tell "a gesture held the window, nothing landed" from "no answer
  arrived, unknown".
- `Pending::answer` was `let _ = self.reply.send(answer)`: the receiver goes with the timed-out
  caller, the send fails, and the frame had already performed the call. Measured by removing the new
  check and running the regression test: revision 2 → 3 and the panel created for a caller that was
  gone.
- The window repaints on input only (X111), so a call queued while nobody touched the window waited
  the whole deadline; the first pointer event afterwards ran it. That is the 196 s landing call.

## Decisions

- A dispatch waits for the first frame that has the window to itself; reads are answered whatever the
  window is doing. A refusal says nothing about the edit a late frame performs, and the plan's shape
  asks a landed call to report its ids while a gesture holds the window (ADR 0223 amends ADR 0207).
- `Pending::abandoned()` is `oneshot::Sender::is_closed()`; `serve_channel` drops such a call before
  anything else, and the frame asks for a repaint while it holds one, so a held call is answered by
  the next frame and not by the next pointer event.
- The deadline answer names the deadline and tells the caller what to do about the unknown; `busy()`
  is gone, so the last word a caller reads is derived from what happened to the document.

## Ruled out

- **Keeping `busy` and only splitting the two sentences.** Cheaper, but a caller that met a gesture
  would still have to retry, and the task's shape asks the opposite: a landed call reports its ids.
- **Exactly-once by an idempotency key.** The remaining race is a caller timing out while the window
  is inside the dispatch; closing it needs a stored answer per call id, which no door has and no
  caller asks for yet (the ADR's consequences say so).
- **Undoing a batch whose answer could not be delivered.** An undo nobody asked for, in a window
  whose person saw the change for a frame; the deadline sentence says "read before repeating" instead.
