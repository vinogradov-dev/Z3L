## The cheap path

- `crates/ui/src/settings.rs` should open with a five-line recipe for a new section — consts, the
  struct with `#[serde(default)]`, the `Settings` field, the clamp in `sanitize`, the rows in
  `viewport_ui` — because those six places were found by reading the file, twice.
- The refusal for a stale `base` should name the numbers it compares: the candidate's line count, the
  budget and the width `set_section` wraps at. One sentence in `state-contract/src/lib.rs` would have
  saved the seven minutes, and the tool already computes all three.

## For the strategy

- Give every refusal the numbers it compares. The plan gate knew the candidate was 94 lines against a
  budget of 70 and said only "rewrite `## Where we are`".
- Say where a new setting section is bolted on, in the file, not in the plan: the six-place walk is
  what a session spends its reading minutes on, and it is the same walk every time.
- Keep the mandatory `dead-end` line and make it name a mechanism, not an activity: this task's value
  for the next session is one sentence about wrap width, not the list of files.
