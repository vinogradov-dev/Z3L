## What was measured

- `crates/ui/src/toolbars/spec.rs:689-720` — the `furniture.panels` group held four cells: the live
  loose *Panel*, *Post*, *Shelf*, and `planned("furniture.panels.contour", …)`.
- `crates/ui/src/editor/creation.rs` — `Editor::create_panel` was four lines over
  `create_panel_sized` with `PanelCreate::default_nominal_size()` and the literal name `"Panel"`;
  `create_panel_sized` already accepts `outline: Option<PanelOutline>` and hands it to `panel.create`.
- `crates/engine/src/panel_cmds/panel.rs:447-466` — a `Contour` outline makes the panel a contour
  panel and the command requires `nominal_size` to equal the ring's measured size.
- `crates/model/src/project/panel_cmds.rs:677-720` — `add_panel_contour_with_bevels` rebases the ring
  at `FrameAnchor::BASE_CORNER`, so the caller passes the work plane's placement unchanged.
- `crates/ui/src/draw.rs` — the draft already knows `is_closed()` and `to_path()`; `Path::to_contour`
  applies the ring rules, so the UI needs no geometry of its own.
- `panel.contour.create` was named only inside `crates/engine`: `plan/notes/U94.md` lists it among
  three orphan commands.

## Decisions

- The cell dispatches **`panel.create` with the ring as `outline`**, not `panel.contour.create`:
  one command, one node, one undo entry. `panel.contour.create` copies a constructive body's ring
  (ADR 0042) and would need a committed path first.
- The intent lives on the editor (`DrawIntent`), not on `DrawDraft` and not in a new tool: one draft,
  two outcomes, and `start_drawing_with` resets it so a sketch tool never inherits a board's intent.
- `ToolActivity::PanelContour` carries no payload and `tool_activity` reads `(DrawTool, DrawIntent)`,
  so the pressed cell is the contour cell and never the sketch polyline whose tool the draft borrows.
- `create_panel_sized` returns the created `Id`, so `commit_panel` names the node instead of reading
  the selection back.
- The cell is enabled only with an open product and a catalogue material, and its hint says the
  gesture; an open chain is refused with `Message::PanelContourOpen`.
- The glyph is `icons::scene::PANEL` (the board the tool makes), which the removed cell used and
  which would otherwise be an unused asset.

## Ruled out

- `panel.contour.create` with an inline ring: a second param shape with two mutually exclusive
  sources, duplicating what `panel.create`'s `outline` already validates.
- Committing the draft as a path and then copying its ring: two nodes, two undo entries and a sketch
  left beside the board.
- Arming a fixed tool (rectangle, circle) as the cell's method: a *panel by contour* that only takes
  rectangles is a sized rectangle panel under a new name.
- Adding `panel.contour.create` to the palette with hand-built parameters: that is U94's inventory
  work, and a palette row is not a place (ADR 0117).

## The cheap path

`outline`, because `panel.contour.create` copies a constructive body's ring (ADR 0042)" — that would
have removed the five-minute dead end, and it belongs in the entry's Shape line.

## For the strategy

When an entry names a command id, the next session should verify the command's parameters before
planning the gesture around it, because an id in a plan is a guess about a signature. A task that
deletes an affordance should name, in its entry, which existing tests and spec rows the deletion
touches, so the red lists arrive at the edit instead of after it. The log's `dead-end` line is what
made this note writable in one pass; keep it mandatory.
