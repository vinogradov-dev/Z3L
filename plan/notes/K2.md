# K2 — What was measured

## What was measured

- No export crate existed. The model already exposes everything the tables need: `Project::products`, `product_of`, `world_placement`, `class`, `properties`; `Panel::nominal_size`, `material`, `last_known_thickness`, `geometry_with_banding`, `nominal_segments`; `PanelOutline::ring_and_sources_for`; `Caption`-style banding records; `Machining`/`Cutout`; `Catalog` and `ClassRow`.
- There is no hardware entity yet (M8), no facade flag, no grain field, no stock group and no supplier group in the catalogue. `facades` therefore derives from the class `opening = closes`, `fittings` from `level = Fitting`, `grain` is always `none`, the facade purchase channel is the class `supply`, glass is read from the material kind, and hinge counts wait for M8.
- `Panel::nominal_contour` returns a `geom::Contour`; `PanelOutline::ring_and_sources_for` returns the same ring in the stored order (a rectangle starts at its zero corner) with one source per segment. The exporter uses that pair for the contour table and for the nominal length of every band, so a contour panel is handed over in its stored order, not in a path-walk order.

## Decisions

- New crate `furnicraft-export` at L3 (deps: model, text, units, geom, serde, serde_json, thiserror), registered in `xtask`, `PROJECT.md` and the `AGENTS.md` crate map.
- One column table (`table::TABLES`) is the only source of the manifest declaration, the JSON Lines writer and the CSV copies. `TableData::push` checks the count and the type of every value, so a row builder cannot drift from the declaration.
- JSONL and the single-file form are written by hand in column order; `serde_json` maps sort keys alphabetically without `preserve_order`, so a map would not keep the declared order. Every table is filled from a `BTreeMap` keyed by its sort key and pushed in that order.
- `products`, `nodes`, `parts`, `banding`, `contours`, `facades`, `fittings`, `machining`, `materials`, `classes`, `properties` are the eleven tables; a table carries a stable `key` string (`node_id+unit`, `node_id+ring+seq`, `machining_id`, `code`).
- Columns that the document cannot fill yet are either omitted (`stock_group`, `hinges`) or stated as a constant (`grain = none`); the contract document records both.
- Numbers are integer micrometres, millidegrees, square millimetres and a 1e9 quaternion scale; the only floating-point step is the model placement/geometry boundary, rounded once into integer cells.
- The fixture carries two products, a loose panel, banded and machined panels, a four-arc contour panel, a facade, a fitting and a user property; the golden package is checked in under `crates/export/tests/golden/package`. A second test asserts two exports of one revision are byte-identical and a third asserts every CSV header matches its declared columns.
- `now_timestamp` formats RFC 3339 without a date crate; a golden export passes no timestamp.
- `plan/rename.md` now names `export` and `text` in the rename alternation: `text` was added after the original measurement and was missing, and K2 adds one more crate.

## Ruled out

- A serde struct per table: the manifest, the writer and the CSV copy would each need a second declaration, which is exactly the drift the task forbids.
- `serde_json::Map` for records: without `preserve_order` it sorts keys, so the declared column order would not reach the file.
- Reading a package back: ADR 0095 makes the `.fcs` the only import format.
- Inventing hardware, grain, stock or supplier fields so the published table looks complete: the model does not carry them, and a guessed column is worse than a missing one.
- Putting the exporter in `project`: the scene envelope is an import format; the package is a one-way output and has its own crate and layer.
