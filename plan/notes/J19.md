# J19 — What was measured

## What was measured

- The four served tools carry the parameter schemas (`schemars` over the struct the command's `run`
  parses), the answers and the refusals, and `command_list` carries `engine::guide()` (ADR 0215).
  Nothing carried a unit: `schemars` writes a field's own doc comment beside its `$ref`, which
  *replaces* the type's description, so `Length`'s "integer micrometres" was dropped on the seven
  fields that describe themselves — `object.cuboid.create`'s three sides (all "Side along the local
  +X"), `object.extrude.create`/`height`, `object.extrude.height.set`, `object.path.extrude`,
  `object.area.extrude`, `panel.bow.set`/`sagitta` — and on all eleven `Placement` fields.
- `crates/mcp/src/server.rs`'s `INSTRUCTIONS` said "a length on the wire is millimetres, an angle is
  degrees": the wire is integer micrometres and integer millidegrees, and a placement's translation
  is the floating-point millimetres. That paragraph is what a client reads before its first call, so
  it was the 1000× of X115 in one sentence.
- No command, query, class row or answer named a side: `Side` lived in `crates/model/src/side.rs`,
  used by the interface's view presets, and `guide().sides` answered a `side -> axis` table.
- `model::class::registry()` rows carry code, slug, label, level, supply and aliases, and
  `TraitSet::fill` (`Fill`) was read by the fill tool only; `docs/domain/classes.md` already spells
  the three pairs `h+d`, `w+d`, `w+h`.

## Decisions

- The owner's rule settled the shape (2026-11-22): **the program must not know a side** — another
  person reads «слева» the other way round — while **the model must**, and that is a recipe for the
  model, not a class or command parameter. So the guide states the frame and the reading, the caller
  says its reading back, and no `side` parameter, class key or answer field exists (ADR 0227).
- The unit is a property of the type, so `params_schema` writes `unit` beside every `$ref` to
  `Length`/`Degrees`/`Placement` from one `UNITS` table, and a test walks all sixty-six schemas. Prose
  per field was refused: it is exactly what drifted, and a new command with a length would have to
  remember it.
- The class row carries `fill` in the registry's own words (`w+d`, `h+d`, `w+h`), derived from
  `TraitSet::fill`, so a name and a form arrive together; a class that fills nothing carries no key.
- The acceptance test is a caller that reads only the surface: units, the shelf's row, the frame, the
  piece's `box`, and the two schemas — then five shelves on `+X` and a rod on `-X`, each asserted by
  `query bounds` against the faces the answers gave (`crates/mcp/tests/served.rs`).

## Ruled out

- **A `side` parameter on `panel.create`, or faces named for the four sides in the `box` answer**
  (X118's Shape): it bakes one reader's meaning of «слева» into the document, and this decision is
  the opposite. X118 keeps the half this task lands — the words reach the caller — and loses the
  other.
- **The guide's `side -> axis` table**: it is the program asserting a vocabulary. The frame and the
  reading rule stay as prose in the same `sides` key, and a test holds that no `axes` table returns.
- **A refusal for a side that cannot exist** (the entry's third `Done` clause): nothing on the
  surface takes a side, so there is nothing to refuse. The clause belonged to the side parameter.
- **Per-field `#[schemars(description = ...)]` or doc prose for the unit**: eleven placement fields
  and seven lengths is a table a new command forgets, which is what the walk's test now catches.
- **`object.cuboid.create`'s placement being the box's centre**: measured — the drawn ring is rebased
  to its centre while the placement is compensated, so a caller's translation is the box's minimum
  corner and `bounds` reports the node around its own centre. The struct's doc comment now says both,
  and the acceptance test reads that sentence.
