# P27 — What was measured

## What was measured

- `check_text` read `plan/map.md`, `plan/debt.md` and `plan/questions.md` with
  `std::fs::read_to_string(root.join(..))` whatever text the caller was writing (lib.rs, the three
  `if let Ok(..)` blocks). `PlanText` already carried `notes` for exactly this reason; the reference
  files were the half nobody passed in.
- J14's measured failure: `cargo xtask file plan/map.md --stdin` wrote a row naming
  `crates/mcp/src/openai.rs` before the file existed on the branch. The gate checked the old map, so
  the write passed; the next verb refused on the new map, and `--repair` could not help, because the
  write that would fix it computed the same violation from the same stale copy.
- Measured again before the fix on the real plan: the same stale row was accepted by a `--dry-run`
  of `file plan/map.md`.

## Decisions

- **`PlanText.references`, beside `notes`.** The shape the entry names: a path the change supplies
  is checked as it will be, and only a path the change leaves alone is read from the disk. A helper
  (`reference_text`) is the only reader of the three files, so the rule has one spelling.
- **`apply` fills it from its own pending files**, filtered by `REFERENCE_FILES`: every verb that
  writes one of the seven inherits the rule without knowing about it, and `check_with` passes
  `None` because it reads a tree that is already on disk.
- **One sentence per violation, unchanged.** The guard already names the row's feature and path; the
  fix is which text it reads, not what it says, so the map row format and `validate.rs` are untouched
  (the `files:` hint's third path was not needed).

## Ruled out

- **Reading the pending files inside `validate.rs`.** The validator takes text, not a workspace, and
  handing it the filesystem would make the gate untestable at the point where it is most useful.
- **Rewriting the map row in `plan/map.md`.** The fix adds no public item the row should carry; the
  row still names `PlanText` and `check_text`.
- **Refusing the write in the `file` verb.** The gate owns this rule, and a second copy in the verb
  would miss the verbs that write the same three files through their own commands.
