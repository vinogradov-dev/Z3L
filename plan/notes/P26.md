# P26 — What was measured

## What was measured

Twenty-five merges of `git log --merges` were replayed: for each, the files the two sides changed on their own commits (`git diff --name-only $base $side`). Files touched on both sides, worst first: `plan/BACKLOG.md` 12, `docs/decisions/README.md` 9, `plan/map.md` 6, `plan/STATUS.md` 4, `AGENTS.md` 4, `crates/engine/src/commands.rs` 3, `app/src/main.rs` 3, `app/src/frame_tests.rs` 3, then `Cargo.lock`, `PROJECT.md`, `crates/engine/src/lib.rs`, `crates/text/src/messages.rs`, `xtask/src/main.rs`.

The stream side of a stream→dev merge was committing the plan: `plan: J7 lands — the window has a chat`, `plan: G4 lands — a drawing's areas are pulled into bodies of their own`, `plan: U120 lands — a round body answers its own places`. Those are `task close` runs inside stream worktrees, which rewrite the shared `plan/BACKLOG.md`, `plan/STATUS.md` and `plan/map.md`.

The ADR number is a second, smaller case: `487bb25` found two records numbered 0104, `b6667ed` renumbered three directory records to 0148–0150 because 'dev claimed 0145-0147 while this branch was open', `7071861` renumbered the price record, and a stream resolved one collision by hand in `f3ea95a` ('the decor record is 0216, because the agent stream holds 0215').

## Decided

The tool enforces the sentence AGENTS.md §6.2 already carried: `plan/` has one writer, the primary checkout. In a checkout whose branch is a declared `stream/<key>`, `task add|start|set|close|reopen|take|defer|drop|phase`, `state` and `file` are refused with a sentence naming the stream, its own two files and the primary; `task step` and `task note` stay open, and only for a task of that stream's own letters (`own_task_refusal`). The stream selection is `crate::stream_checkout` — branch `stream/<key>` plus a key the `STREAMS:` line declares — reused by `docs`.

The decision index follows the same rule, which is why `docs::check_in_stream` exists: `docs/decisions/README.md` is one table in one file, so a stream that writes a decision cannot add the row without meeting `dev` in the same hunk. A stream checkout names the rows waiting for the primary and stays green; the primary's own run is strict and fails until it adds them. Without that, the change would have left a stream unable to run `cargo xtask ci` at all.

## Ruled out

- **Generating `docs/decisions/README.md`** (`cargo xtask docs --write`): the row is exactly the file's number, title and `Status:`, so it would work, but both sides still change one line of one table, so the merge still conflicts — it only makes the resolution mechanical. The tolerant-check design above makes the conflict disappear instead.
- **A number range per stream** (J claims 02xx): it breaks the single sequence every ADR citation reads, a stream's task may move, and the range has to be renegotiated when it runs out.
- **`cargo xtask docs renumber`**: a verb that rewrites the file name, the H1, the index row and every `ADR NNNN` in the tree. It resolves a collision in one command, but the collision itself should not happen; the gate now refuses two records under one number, and the merge is a human decision about which record keeps it.

## What still conflicts

Code hot spots are untouched by this: `crates/engine/src/commands.rs`, `app/src/main.rs`, `crates/text/src/messages.rs`, `Cargo.lock`. `AGENTS.md` and `PROJECT.md` are the constitution and the crate map, edited rarely and by the primary; they were both-sided four and two times in those twenty-five merges and are not addressed here.
