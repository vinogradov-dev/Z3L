# J3 — What was measured

## What was measured

- `app/src/cli/query.rs` held all five derivations — the node walk, the box rows, the published
  `parts` table through `OrderPackage::build`, the panel diagnostics and `Project::niche` — inside the
  binary crate, 324 production lines and 179 test lines. `app` is layer 8 and `mcp` is layer 7
  (ADR 0186), so the crate the tool will live in cannot reach a line of it: the read model was
  reachable by a terminal and by nothing else.
- `Session` already reached every input of the four answers that are not `parts`: `project()`,
  `directory()` (the catalogue the cut list needs) and `contact()` (the adapter `niche` measures a
  splayed wall through). Only the cut list needed a crate the engine did not have: `export`, layer 3.
- The command line read its report as loose words plus two flags, so `parts --at 1,2,3` and
  `diagnostics --id 5` were silently answered with the flag ignored, and no schema of a question
  existed for a caller to build a request from.
- `schemars` and `serde` were already `engine` dependencies since J2, and `model::Id` already derives
  both, so the selector's wire form and schema cost no new dependency.

## Decisions

- `engine::Query` is the typed selector: five variants, no argument a variant does not read, `serde` +
  `JsonSchema` on the type, and `Query::NAMES` / `name()` as the one list of stable names. `Session::read`
  answers it, and `app/src/cli/query.rs` is only the door: words to a `Query`, rows to an envelope.
- `engine` gains `export` for the one derivation it does not own. The alternative — a second cut list
  in `engine` — is the second truth ADR 0095 exists to prevent, and the edge follows the layers.
- The resource table lives in the door (four rows, each naming the question it reads) and moves into
  `mcp` with the tool projection in J5. `engine` answers questions and learns no URI.
- `niche --id` is resolved to a point by the door, so the selector never carries two ways to name one
  place.
- The envelope keeps `query`, `document.file`, `document.revision` and adds `uri` only for a resource
  read, so the word form and the URI form stay byte-identical in `rows` — which is what the new test
  compares.

## Ruled out

- **A second crate for the read model.** `engine` owns the session and the derivations the answers
  reuse; a crate beside it would have to depend on `engine` and be depended on by `mcp` for four
  functions.
- **`QueryKind` in the door beside `Query` in the engine.** Two enums with the same five names drift
  the day a sixth question lands; the door reads `Query::NAMES` instead.
- **A `sight` parameter on `Session::read`.** No caller has a hidden set today (the debt entry files
  selection and open containers in `ui::Editor`); `Sight::none()` stays the documented reading of
  ADR 0183 and the parameter arrives with the session's own hidden set.
- **A hand-written tool schema for `query`.** The selector derives `JsonSchema` the way a command's
  parameters do (ADR 0195); a table would be the drift J2 closed.
- **`niche` as a resource.** It measures a place the caller chose, so caching its answer by revision
  would be a lie.
