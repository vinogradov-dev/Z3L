# X114 — the channel could not save the scene it changed

the channel could not save the scene it changed

## What was measured

- `app/src/main.rs::answer_channel` dispatched with `mcp::Door::Window`, a unit variant, and
  `crates/mcp/src/server.rs::dispatch` mapped it to `Write::Window`: every window batch answered
  `"write": "window", "written": false` and the tab kept its dirty marker, so an agent that built a
  wardrobe owned nothing it made (plan/BACKLOG.md, ADR 0005, ADR 0188).
- The headless door already had the writer: `app/src/cli/served.rs::SceneWriter` (the path plus the
  preserved sections) implemented `mcp::SceneSink`, and `project::SceneFile` performs the atomic
  write. `app/src/document.rs::save` kept a second copy of the same three steps — write,
  `session.mark_saved()`, `file.set_path` — for the person.
- `mcp::report::batch` carried the file's state in `write` and `written`, and a sentence in
  `write_error` for a failed write only.

## Decisions

- **The save belongs to the batch and it is opt-in**: `BatchRequest::save`, and `RunRequest::save`
  for the batch of one. A window's document is written only when the caller asks. A headless session
  keeps writing every landed batch that changed the document, because `z3l mcp serve <scene>` named
  the file when it started and that naming is the same ask made once; the difference between the two
  doors is written on `mcp::Door` rather than left to a reader of the field.
- **`Door::Window { sink }`**: the shell hands the door the writer it owns, and `None` while the tab
  has no path. The ask then answers `write: no_path`, a failure carrying `NO_PATH_NOTE` in
  `write_error`, which names the person's *Save as*: a caller never chooses a path (ADR 0188).
- **An asked save ignores `content_changed`**: the caller asks for the document as it stands, and a
  tab dirty from an earlier batch is worth writing even when this batch leaves it identical. The
  headless write keeps the guard, because its promise is the batch and not the document.
- **One writer, `app/src/scene_writer.rs`**: `SceneWriter` moved out of `cli/served.rs`, and
  `Document::save` uses it, so the person's *Save*, a headless batch and a caller's save write the
  same bytes with the same preserved sections; only the path and the dirty marker differ.
- **The dirty marker clears on the wire's own word**: `mcp::Answer::written()` reads `written` back
  and `answer_channel` calls `Document::mark_saved()` on it — a save a caller asked for is the
  person's *Save* performed on their document, and the file holds the revision the answer named.
- The save reaches the path the scene already has, and `settings.remember` does not run, because no
  path changed.

## Ruled out

- **A sixth tool (`scene_save`)**: a field states the ask in one call; a tool of its own would need a
  `Call` variant, a tool row and an answer shape beside `command_batch`, and an agent that builds and
  saves would make two round trips for one operation.
- **The window writing on every landed batch**: what J6 ruled out, and still wrong — a file nobody
  asked for can overwrite work the person has not saved.
- **Requiring `save` on the headless door too**: the promise of `z3l mcp serve <scene>` and the
  `written: true` / `sink.writes()` assertions of `crates/mcp/tests/served.rs` are "a landed batch is
  written once", and the flag would break the door that already writes.
- **A path in the request** (`"save": "<path>"`): ADR 0188 keeps the channel from being a way to
  reach a path.
- **Marking the document saved inside `SceneSink::save`**: the sink sees a `&Project` and nothing
  else, and a writer that reached the session would be a second path into the document.

## Tests

- `app/src/frame_tests.rs::a_save_a_caller_asks_for_writes_the_scene_and_marks_the_tab_saved` — the
  file reads back with the revision the answer named, and the tab is clean.
- `app/src/frame_tests.rs::a_save_a_scene_with_no_path_cannot_take_is_refused_and_writes_no_file` —
  `write: no_path`, a sentence naming *Save as*, no scene file anywhere in the folder.
- `app/src/frame_tests.rs::a_batch_that_did_not_ask_for_the_save_leaves_the_file_alone` —
  `write: window`, and the file still holds the revision the person saved.
- `crates/mcp/tests/channel.rs::a_save_a_scene_with_no_path_cannot_take_is_a_refusal_that_names_the_persons_act`
  — the wire's own words at the door, with no window.
- `app/src/scene_writer.rs` — the preserved sections ride back, and a refused write names the file.
