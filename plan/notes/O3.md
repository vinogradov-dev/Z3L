# O3 — The directory is packages; a part is a document; a hole is derived

## Measured before the decision

- `crates/model/src/catalog.rs` — 762 lines, two tables (`PanelMaterial`, `EdgeBandingMaterial`),
  `MaterialId(u64)`, one mock JSON file, immutable per session.
- `MaterialId` is named in 21 Rust files; `Catalog` in 23 (measured on `015984b`). A rename is a
  tree-wide change and needs a narrow gate on the type before any caller moves (§1.5).
- `MachiningParams` has exactly one kind, `Cutout` (`crates/model/src/panel/machining.rs`). There is no
  bore, no groove, no milling, so nothing could consume a tool reference today.
- What the design leans on already exists: the class registry with traits (ADR 0094), typed node
  properties (ADR 0034), `Path`/`Contour`, the atomic writer in `app/src/settings_store.rs`, the scene
  envelope in `crates/project`, and `crates/text` for report wording.
- The three records were numbered 0145-0147 on paper; `dev` claimed those numbers while the branch
  was open, and they are 0148-0150 now. One sequence, one writer: a branch cannot reserve a number.

## Decided

- The directory is a set of packages of items with composite `ItemId (package, serial)`; kinds,
  properties and families are registry rows, code reads traits, never a kind code.
- `Appearance` (render) and `Finish` (report, composed by `crates/text`) are different blocks; a facade
  may legitimately disagree between them.
- A hardware model is our own part document, not a mesh plus an overlay; the scene holds an instance,
  and `catalogue.detach` is the only way to own the nodes.
- A hole is the crossing of a drilling object with a panel body; a panel never stores one.
- A tool is stored only where its radius changes the shape (contour milling); a groove stores width and
  the park picks the saw.
- Placement rules are typed tables with completeness and overlap checks; there is no expression
  language in a package.
- The order package is the only frozen copy; the live document re-derives and the undo history survives
  a directory revision.

## Ruled out, with the reason

- **SQLite / any `-sys` store** — binds C, forbidden by AGENTS §2. `redb` is the pure-Rust candidate if
  the folder stops suiting; it waits behind `DirectorySource` for a measured need.
- **Mesh baking plus a semantic overlay** — invents a second geometry format, a second cache and a
  second viewer; our own document format already carries anchors, classes and properties.
- **Copy the part's nodes on insertion** — freezes the model at the moment of insertion, which is the
  one thing the workshop needs the opposite of.
- **Selecting a plug by RGB proximity** — shops reason in families ("oak corpus, brown plug"), and a
  decor, its banding and its plug must meet in one registry row with a rank.
- **A formula surface for rules** — supplier hinge data is literally a lookup table; prototypes remain
  the only place arithmetic is open (`prototypes.md` §11), and if granted it is one shared evaluator.
- **A price overlay layer** — the owner keeps prices as item properties (as К3 did); only stock on
  hand, which is volatile, becomes an overlay.
- **A 3D viewer inside the directory application** — authoring a part is ordinary editor work on an
  empty document, so the directory application stays a data application.
