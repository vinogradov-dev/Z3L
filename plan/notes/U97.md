# U97 — the armed tool's card and the inspector mirror one draft

## What was measured

- `crates/ui/src/command_bar.rs` was one surface for two tools: `show_command_bar` (a pull's height) and `show_box_bar` (a box's height), both at the viewport's bottom centre; the fill's two gaps were a second overlay, `distance.rs::DistanceFields::show`, one `Area` per gap.
- `distance.rs` carried the shared field's real state (pins, locks, Tab, Escape, refusals) in `DistanceFields`; the value itself lived in `Distances`.
- The inspector (`crates/ui/src/editor/cards.rs::Editor::show_card`) had no tool section: while a tool was armed the right panel showed only the selected node.
- A box height typed into the old bar survived only because the pointer had to travel to the bar: `document.rs::update_box` recomputed the height from `response.hover_pos()` every frame.

## Decisions

- One module owns the surface: `crates/ui/src/tool_card.rs` (`ToolView`, `ToolRow`, `ToolParam`, `show`, `section`, `body`, `row_ui`). `command_bar.rs` is gone; `DistanceFields` still owns the gaps' keyboard and pins but draws through the card (`DistanceFields::show` builds `Distances::rows()`), so ADR 0119's one layout, one commit path and one edit scope hold without moving the measurement into a widget.
- One draft, two readers: `Distances::rows()` is the only place a gap becomes a row, `Document::height_view` builds the height rows, `Document::tool_view` is what the inspector draws, and `Document::apply_tool_outcome` takes both surfaces' numbers through one path (`pull_box_height`, `preview_extrude`, `DistanceFields::apply`).
- The card freezes its anchor while the pointer is inside it (`Document::card_anchor`): a card that chases the pointer slides out from under the hand reaching for its field, which the first frame test proved.
- A focused field owns the box height: `update_box` skips the pointer's pull while `text_edit_focused()`, because the card's field is 18 pt from the pointer and would otherwise be overwritten every frame.
- Enter still commits the whole tool in `handle_keys`; the card adds no key reader. The check and cross are drawn only for a tool with one explicit commit (a box, a pull); a fill commits on its click.
- `Chrome::tool` carries the card's last-frame rectangle, so a press on it is chrome in `viewport`, under the work cursor and in the split-view border test.

## Ruled out

- Moving `Distances` into the card: the measurement, its pins and its refusals are not a widget's state, and the translate drag reuses them (`show_move_distances`).
- Editing `command_bar.rs` to look like the card: two modules would have drawn one surface and `HOST_OWNERS` would have kept a second owner of the same plate.
- A card that follows the pointer every frame: measured by `a_press_inside_the_card_is_chrome_and_never_a_pick_or_a_finish`, which failed before `card_anchor`.
- Keeping the view cluster lifted by the old bar's height: the card no longer takes the bottom centre, so `view_cluster::show` is handed `0.0`.
