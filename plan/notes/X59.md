# X59 — a click rejects by the box and casts only what the ray reaches

a click rejects by the box and casts only what the ray reaches

## What was measured

- `crates/scene/src/ray.rs`, `ray_hit_drawable`: the cast walked the whole index buffer of a drawable
  and transformed every vertex it touched, three per triangle, with no way to leave early.
  `pick_surface` called it for every drawable of the frame, so a click was O(total triangles):
  16 / 64 / 161 ms at 500 / 2 000 / 5 000 spheres (0.48 M / 1.9 M / 4.8 M triangles). The press
  that opens a rubber band ran the same loop through `pick_surface` before it started.
- The value a rejection needs already existed: `Drawable::local_bounds` holds the box the mesh cache
  measured (X56) and `Drawable::world_bounds()` turns it into the world box a view culls by (X58).
  Nothing in the pick path read it.
- After, measured by the new probe (`app/src/scene_build.rs`,
  `a_click_costs_the_objects_and_not_their_triangles`, dev profile with opt-level 2, best of five,
  the same 32 x 16 sphere field): 0.06 / 0.25 / 0.62 ms over empty space and 0.14 / 0.35 / 0.79 ms
  through the field, against 16 / 64 / 161 ms.

## Decisions

- **The box test is the slab test the product envelope already used.** `ray_slab` takes a `min` and
  a `max` instead of a size, and `ray_hit_box(ray, Aabb)` is its crate-visible face: one function
  decides whether a ray enters a box, so an envelope and a drawable cannot disagree on a boundary.
- **A miss is not the only rejection: a box behind the nearest hit ends the drawable.**
  `ray_hit_drawable` takes `limit` — the nearest hit so far, `f64::INFINITY` at the start — and
  returns `None` when the entry distance is past it, because a box holds its own triangles.
  `pick_surface` threads its `nearest` through. Without it a click on the model would still test
  every object's box and the triangles of everything nearer than nothing.
- **An unmeasured box is not a rejection.** `with_box(…, None)` means the extent was never
  measured, so the drawable is cast anyway: the box narrows a pick, it never hides an object.
- **A test-only thread-local counts the triangles a cast tested**, as `VERTICES_TRANSFORMED` does
  for the scene walk (X56). The dense-frame test asserts zero over empty space, so a session that
  puts the whole-mesh loop back fails even on a machine fast enough to hide it in the timing.
- The counter cannot serve the timing probe: `app` cannot see another crate's `#[cfg(test)]` items.
  The counter test is therefore a `scene` unit test over 2 000 drawables of 64 triangles, and the
  probe in the shell measures the sphere field.

## Ruled out

- **A BVH over the frame's triangles now.** The box test answers the worst case in 0.6 ms at 4.8 M
  triangles, so the build cost a BVH would add per mesh buys nothing measurable yet; it stays the
  next step only if a measurement asks for it.
- **Sorting the drawables by depth before the cast.** It would let `limit` prune more often, but it
  costs a sort per click and the demo scene's order already finds a near object first.
- **A tighter box for tilted round bodies.** The world box is the box of the turned box (X56), so a
  tilted ball's box is larger than the ball and survives a ray that misses it; the per-triangle loop
  then runs on that one object. That is the case X62 owns, not this entry.
