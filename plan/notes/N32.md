# N32 — the role a plane implies, and the two 45-degree ties

## What was measured

- `crates/model/src/panel/classify.rs` held `classify_outline` only: nothing in `model` read a
  plane, so no class could be derived anywhere.
- `crates/engine/src/panel_cmds/panel.rs::create_panel` writes `params.class` when a caller names
  one and otherwise leaves the panel unclassified — ADR 0034's default.
- The one creation path with a plane and no niche was `crates/ui/src/editor/drawing.rs::
  commit_panel`: it hands `create_panel_sized` the work plane's placement and `class: None`. The
  fill names its class (`crates/engine/src/panel_cmds/fill.rs`), and the standard part names the
  class of its kind, so both already win over any derivation.
- A creation that carries a class wrote it as a second model change: the app's
  `the_contour_cell_cuts_a_panel_to_the_ring_the_pointer_drew` counts revisions and answered 14
  where the frame left 13 once the class was written after the board.
- The class rules are real once a part is classified: a shelf refuses a `Post` cutout
  (`a_cutout_that_trims_a_narrow_core_is_accepted` failed while the derivation sat in
  `create_panel`).

## Decisions

- **`model::role_of_plane(normal) -> Option<ClassCode>`** carries the rule, in `classify.rs` beside
  `classify_outline`. Shelf within 45° of the horizontal (tie included); otherwise post within 45°
  of the parent's `X` axis, the tie to the wall. Both thresholds are compared squared, so 45° is
  exact on each side.
- **The caller decides, the command does not derive.** The contour tool reads the work plane's
  normal — the panel's thickness axis — and passes the class into `panel.create`; a caller that
  names a class still wins, which is what keeps the fill's section pair and the standard part's
  kind intact. The rule therefore lands in the creation paths that have no niche, as the entry
  asked, and `panel.create` stays a command that writes what it is told.
- **One creation, one revision.** A class written by a create command settles the revision to the
  one the command started from plus one (`Project::settle_revision`), which is ADR 0234's rule
  applied to a creation: the board and its role are one entry.
- **A vector that is not a direction answers `None`**, and the part stays unclassified: there is no
  honest role for a zero or non-finite normal, and ADR 0034's default is the answer rather than a
  guessed class.

## Ruled out

- **Deriving inside `create_panel`** (tried, reverted): every board became a shelf, so the class
  rules began refusing machining a maker had already drawn on that board, and the document needed a
  revision settle to stay one entry. The entry's Shape puts the rule in the creation paths.
- **A total function with a fallback role for a broken normal**: any fallback is a class the plane
  does not imply, and a maker cannot tell it from a measured one.
- **Reading the plane from the ring's own vertices** instead of the work plane's frame: the ring is
  stored in the panel's local frame, whose normal is the thickness axis by construction, so the
  frame is the plane and the vertices would only restate it.
