# X110 — a body answers the box it occupies, in its own frame and in the world

a body answers the box it occupies, in its own frame and in the world

## What was measured

- `Query` (`crates/engine/src/read.rs`) held five questions: `tree`, `box`, `parts`,
  `diagnostics`, `niche`. `box` answered only a product's authored envelope, and refused every other
  node with `node N is not a product; box reports the box a product reserves`, so a caller that had
  just built a 200 x 300 x 600 body had nothing to ask it about.
- The derivations already existed and were unreachable: `object_bounds_mm` and `panel_bounds`
  (`crates/model/src/tree.rs`) produce a body's and a container's box, and
  `Project::bounds_center_local` (`crates/model/src/project/query.rs`) built the union and then threw
  away everything but its centre. The only budget for a box on the wire was a centre.
- The defect's first measurement was over the channel: after `object.cuboid.create` the answer named
  the id, and no call reported the node's own bounds, its size or its mesh.

## Decisions

- **A sixth question, `bounds`, with a required node — not a widened `box`.** The two answer
  different questions about one id: `box` is the authored envelope a product reserves, `bounds` is
  the measured box the node occupies. One answer carrying both would make every existing `box`
  reader read a discriminant to learn which number it got.
- **Every key names its frame.** `local_min_mm`, `local_max_mm` and `local_size_mm` are the node's
  own axes, where its box never turns; `world_min_mm`, `world_max_mm` and `world_corners_mm` are the
  document's, with the eight corners of the local box through the node's placement. The `niche`
  answer spells its world keys `min_mm` and `max_mm`; this answer does not copy that, because a
  caller reads the answer without the source and an unprefixed pair beside a `local_` pair leaves it
  guessing which is which (the defect X115 names on units, and X118 on sides).
- **One derivation.** `Project::bounds_local(id) -> Option<(DVec3, DVec3)>` is public and
  `bounds_center_local` is its centre, so the pivot's centre, the tests and the answer cannot
  disagree about where a node stands.
- **No geometry is a sentence, not an empty answer.** A camera, a light and a container with no part
  in it answer `QueryError::NoGeometry`, which says `bounds` measures a panel, a body, a product or a
  container with a part in it — the caller can act on it.
- **`bounds` is a tool argument, not a resource.** It takes a node, like `niche` takes a point
  (ADR 0196): a resource caches an answer whose inputs change only with the document.
- **One word list.** The CLI's `Ask` word map (`app/src/cli/query.rs`) and its `check` learned the
  word in the same change; without that the new name would have fallen through to `niche`'s arm.

## Ruled out

- **A resource `z3l://scene/bounds`.** A node id is a caller's choice, and the resource table holds
  only the questions that take no argument.
- **Micrometre integers for the local box.** A container's union goes through placements in
  millimetres, so the exact integer form exists only for a panel and a body; the `niche` answer
  already puts these numbers under `_mm`, and `box` keeps `size_um`.
- **A stored bounds.** The box is derived on read from the document and the placements, like a
  product's content bounds (ADR 0159), so no reference can go stale.
