# U99 — the niche is one atom, and the fill is its first consumer

the niche becomes a tool of its own, and fill, a shelf and a report consume the same value

## Brief (five lines)

The screen is the viewport and the status bar while the Furniture tab's new *Niche* cell (or `V`)
owns the pointer. The person's goal is to read the empty space inside the open product — the same
space a post or a shelf would fill — without creating anything. The one primary action is pointing:
the cell has no commit, no number and no button; Enter and the plus are absent on purpose. The
density is a transient atom (a wireframe box and one readout), not a panel. Nothing is removed.

## What was measured

- `app/src/fill_gizmo.rs` held the whole mechanism: `pointer_point`/`box_entry` (the
  cursor rule), `MEASURE_STEP_MM` (the still-pointer cache), `FillGizmo::measured`, and
  `plan_at` → `Project::fill_plan`, which called `Project::niche` itself. A second tool that wanted
  the cell had to copy all four.
- `Project::niche` (`crates/model/src/project/niche.rs:392`) answers the convex cell from any point,
  and `Project::fill_plan` (`crates/model/src/project/fill.rs:135`) re-measured it. Measured on an
  empty 600 x 560 x 720 frame: the cell is the envelope, `local_min` zero, `size` the envelope.
- `Project::fill_plan` had seven parameters with `&self` — one below `clippy::too_many_arguments`;
  adding the niche as an eighth would have been refused, so the numbers became one value.
- `crates/ui/src/inventory.rs` had 57 command rows, one atom (`sketch.measure.length`) and an
  `ATOMS` list the gate reads; the ribbon id namespace test (`every_id_is_unique_and_namespaced_by_its_parent`)
  requires a cell id to start with its group id, so the atom's row id (`probe.void`) cannot be the
  cell id (`furniture.panels.void`).
- `crates/ui/src/toolbars/ready.rs` gates a fill on an open product and a panel material; the niche
  needs only the product, because it takes no thickness.
- The status bar draws its centre zone from `StatusInfo`; the ruler's value already lives there
  (U98), so a second readout needed one field, not a second strip.
- `crates/ui/src/icons.rs` asserts one icon file per inventory row and a 108-entry set; the niche's
  drawing is the 108th, and `assets/README.md` names it under the `scene` theme.

## Decisions

- **The atom lives in `crates/ui/src/void.rs`.** It keeps the last point and either the cell or the
  refusal, re-measures only when the pointer moved half a millimetre, and exposes `niche`, `point`,
  `product`, `refusal` and `size` (three `Length`s, computed from the cell's quantised corners).
  It takes the point, not the camera: `pointer_point` is the free function the shell calls, so the
  atom has no `Camera`, no `egui` and no document write.
- **One `Void` per editor, not one per arm.** `Editor` owns the value and a `void_armed` flag; a
  fill arm writes into the same atom, so the fill ghost, the status bar and the plan read one cell
  in one frame. Two atoms would have been the defect ADR 0118 names, in a different shape.
- **`FillRequest` carries the five numbers.** `fill_plan(product, request)` and
  `fill_plan_in(niche, product, request)` share one body; the atom's cell is an argument, so the
  fill never probes again. `fill_plan` still measures its own niche for a caller without one (the
  tests and a future report).
- **The cell's box is the ghost.** `Niche::local_min` + `size` is the same pair the plan starts
  from, so the overlay and the report row print one number; a wireframe says the void is empty, and
  the three sides sit at the middle of the box in `Length`'s own format.
- **The report row is the status bar**, not an inspector card: a niche has no parameter to type, and
  ADR 0118 already put the ruler's value in the same centre zone. The left zone says what to point
  at; a pointer outside the product clears the atom so the row says why instead of printing a stale
  cell.
- **Two entry points, one toggle.** The Furniture tab's `furniture.panels.void` cell sits with Post
  and Shelf because a maker reads the gap and the part together; `V` is filed under the cell (the
  ribbon prints a method's key); the `probe.void` row also claims `Place::ContextMenu`, so a right
  click on a product opens it and arms the tool; `NodeAction::ArmVoid` opens the product first,
  because a niche belongs to the open one (ADR 0098).
- **The icon is a measured region, not a board.** Four corner brackets (`Reference` ink) around a
  toned rectangle: every other Furniture cell is a solid or a plate, and a filled box would read as
  a third one. Measured at 96 px and at the gate's 16/20 px.

## Ruled out

- A second probe or a second cache inside `FillGizmo`: the plan is keyed by the cell value, so a
  still pointer plans nothing and the atom owns the measurement.
- Reusing `Project::fill_plan` from the fill path: it measures the niche, which is the second probe.
- A tool card for the niche: it has no parameter, so ADR 0119's card would be an empty floating box.
- Storing the cell in the document, or an undo entry for arming: it is information (ADR 0118, 0029).
- Putting the niche cell in a new "Space" group: one cell under a second caption adds a word to the
  strip and says nothing the Panels group does not.
- An inspector section for the reading: the status bar is already the one row that reports a
  transient value, and the inspector's live section mirrors a *draft* with fields (U97).

## Verification

- Headless: `void::tests` (the cell, the refusal, the still pointer, the cursor rule and the turned
  product — moved from `fill_gizmo`), `editor::tests::one_measured_niche_serves_the_fill_plan_and_the_report_row`
  (one measurement, then the plan and the three sides), `node_actions::tests::a_product_offers_the_niche_and_a_panel_does_not`,
  and `frame_tests::the_niche_is_a_tool_the_ribbon_arms_and_the_fill_reads` (the cell arms from the
  strip, the bar prints the cell, Escape writes nothing, and the fill's ghost carries the same cell
  at the same pointer).
- Eyes: the icon was rasterised offscreen to `target/icon-shot.png` and looked at (a temporary
  ignored test, removed); the ribbon and the overlay were not rendered — no GPU in this session.
