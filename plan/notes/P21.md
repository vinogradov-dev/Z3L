# P21 — the writer and the gate now agree on the label's spelling

the writer and the gate now agree on the label's spelling

## What was measured

- `edit::set_field` (`state-contract/src/edit.rs:194`) took `--field shape` and handed it as typed to
  `field_lines`, so the line landed `  shape: …`; `known_label` and `edit::label_of` matched
  case-insensitively, so `set_field` then *found* the field it had just misspelled.
- Reproduced with `cargo xtask task set P21 --field shape --body repro --dry-run`: the diff showed
  `+   shape: repro` and the gate said `plan: ok`.
- The backlog carried 27 such fields in 13 entries (Y6, P19, Y3, N36, N35, G3, X73, X76, X72, N26, X51,
  U93, U83) — 25 of them in `## Done`, because the writer allowed any case and hand-edited entries
  followed. The longest body line is 95 characters, exactly `FIELD_WIDTH`.

## Decisions

- **`parse::canonical_label`** is the one place that maps a typed label to the declared one (`Rules`,
  `Why`, `Shape`, `Done`, `Commits`, `files`). `set_field` refuses an invented label as before and now
  writes the declared spelling for a known one; `cli::write::set` canonicalises first, so `--field FILES`
  takes the `files:` branch instead of inserting a second hint.
- The gate gained `label_case_violations`: a line that starts `shape:` is a violation naming
  `Shape:`. It looks at the start of a line only, which is where the writer puts a field, so the legal
  mid-line form `— rules: B1` that closes a lead is not flagged.
- The 27 historical fields were rewritten through the tool, not by hand: `cargo xtask task set <ID>
  --field <Label> --stdin --repair`, one write per field, so each landed through the gate. The writer
  normalises a continuation line to a two-space indent, which is why the diff is wider than 27 lines;
  a field-by-field comparison of the old and the new file (label, body) shows no other change.
- P19's body was re-wrapped on purpose: it read `… to run its four commits: plan/rename.md …`, and the
  word `commits:` was a field boundary to the parser, so the rewrite moved it and the sentence now reads
  `commits — plan/rename.md …`. The ambiguity itself is a `[plan]` debt entry, not a change here.

## Ruled out

- Refusing the write instead of canonicalising: `--field shape` is the natural way to type it and the
  parser reads the field anyway, so a refusal would only teach a spelling without fixing the file.
- Flagging a label anywhere it starts a word, as `parse::split_fields` finds it: a lead line ends with
  `— rules: B1` by design, so that rule would reject the plan the tool itself writes.
