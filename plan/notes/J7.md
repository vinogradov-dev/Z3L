# J7 — the panel, the turn and the person's two modes

## What was measured

- `engine::Session` had no mode and no read-only gate of any kind: the 64 commands of the registry
  all mutate, `Session::batch` already had `dry_run` (ADR 0198), and the person's own path is
  `dispatch`/`dispatch_in`, which never goes through a batch.
- `crates/mcp` had one dispatch function for both agent doors (`server::dispatch(&mut Session,
  &BatchRequest, Door)`), so "the dispatcher" ADR 0190 names is one place, and the window's channel
  (`app::answer_channel`) already goes through it.
- A batch was its own undo entry unconditionally: `Session::land` closed any open edit scope and
  pushed `self.project` before installing the trial. "One message is one undo entry" (ADR 0187)
  therefore could not be expressed with `Session::batch` alone.
- The shell's frame answers both slow workers at the boundary already (`serve_channel`,
  `take_directory`, `take_pick`), which is where a chat turn belongs.
- Frame tests can reach the private state of `App` (`harness.app`), so a test installs a backend and a
  message without any test-only public API; `panel.create` needs an open product and a catalogue, so
  the fixture is `testkit::sample_product_project()` plus `sample_catalog()` and `open_product`.

## Decisions

- **The mode is the session's, the gate is the agent's.** `AgentMode` lives on `Session`; the person's
  `dispatch` is not gated, so the switch silences the agent doors (tool server, channel, chat) and
  never the person's own field. `Session::agent_batch` applies `dry_run` in `plan` and passes the
  request's own options in `build`.
- **A headless session is born in `build`, a window tab in `plan`.** A process that started a tool
  server chose to let it write, and its plan is `--dry-run`; a tab has a person in front of the
  switch, so `plan_mode(session)` sets `plan` for both `App::build` and `App::empty_tab`.
- **`land` learns a scope, `batch_in`/`agent_batch_in` are the merge.** The batch keeps its own
  all-or-nothing trial; only the *entry* is shared. The first batch of a turn pushes the state before
  the message and opens the scope, the rest replace the document inside it, and the shell closes the
  scope when the turn ends. A batch with no scope behaves exactly as before.
- **The backend is `ask`/`take`, and the turn advances one step per frame.** A blocking `reply`
  would freeze the frame the moment the HTTP adapter lands; `ask` starts the work and returns, `take`
  answers when the work is done. The scripted backend answers at once, which is what makes the whole
  turn testable.
- **The turn dispatches one batch per reply, inside one scope per message.** Undo takes the whole
  message back; a turn that dispatched nothing leaves no entry. A refusal does not end the turn —
  ADR 0187 says the refusal is a result the model can act on — the budget does.
- **The panel is a `Window` with `Ctrl+J`, drawn by `app/src/chat.rs`** (ADR 0208). `ui` may not
  depend on `mcp`, so a panel in `crates/ui` was impossible without a second registry; a third
  floating side panel would narrow the scene for a conversation.
- **No model, no pretence.** With `backend: None` the panel names the state, the field is disabled
  and the mode switch, the transcript and the checklist still draw. Nothing in a shipped window
  reaches the network.

## Ruled out

- **A `reading` flag inside `Session::run`.** It would silence the person's own commands the moment
  the panel is in plan — the switch would be over the whole editor, which ADR 0190 does not say — and
  a per-command "mutates" column would be a new registry field for a fact that is already universal:
  every registered command mutates.
- **Filtering the mutating commands out of `command_list`.** ADR 0190 rules it out for the same
  reason: the surface is coarse, and a model that is not told about an id is one prompt away from
  guessing it.
- **A turn that runs to completion in one frame.** It is simpler and wrong: the person's stop has no
  frame to land in, and the HTTP adapter would have to block the frame it was asked in.
- **Hiding the tools in plan mode / a tool that flips the mode.** Both are theatre (ADR 0190): the
  switch must be the person's and the list must be the same in both modes.
- **The HTTP adapter, the consent card and the key file in this task.** They are ADR 0189's other
  half and its one dependency exception (`openssl-sys` with a test over the resolved graph); filed as
  J14, with the shape and the done clauses written from 0189.
- **Renaming the root or an existing panel as the test's mutation.** The turn's tests need a change
  the class rules allow, and a part is born only inside an open product, so the fixture builds a
  product and then a panel.

## What a next session should know

- `Chat::serve` is driven by `App::serve_chat(lang)` at the top of `App::frame`, after
  `serve_channel`; a gesture in flight pauses the turn, it does not fail it.
- The panel's `HOST_OWNERS` row is `app/src/chat.rs` in `xtask/src/ui_rules.rs`; the inventory rows
  are `ASSISTANT_OPEN` in `ACTIONS` and `KEYS` (`Ctrl+J`).
- `Shortcuts::pressed_count` is a hand-written list, so a new field must be added there too or the
  key table's own test fails with "runs more than one action".
- The end-to-end turn tests are `app/src/frame_tests.rs`: `a_chat_turn_lands_one_undo_entry…`,
  `the_panel_in_plan_mode_draws_the_plan_and_writes_nothing`,
  `a_stopped_turn_leaves_the_document_as_its_last_answer_did`, `the_assistant_panel_opens_on_its_key…`.
