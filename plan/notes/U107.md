# U107 — the shadow is a view mode, with one intensity beside its switch

## What was measured

- `app/src/view_cluster.rs` held the switch (`ViewCluster::contact_shadows`) and `app/src/document.rs`
  wrote one frame-wide `ContactShadows` from it, so two split cells could not disagree; the strength
  was a Settings › View slider (`ViewportSettings::shadow_strength`) and the frame-wide write also
  took it, so the renderer's per-view uniform already existed and only the *value* was global.
- `crates/render/src/lib.rs`: `render_views` writes one `CameraUniform` per view, and its
  `shadow` field is the last thing `shadow_uniform` builds — the mask itself is built once, in the
  ground slot, from the frame. A per-view switch therefore costs one uniform field and no upload.
- `crates/ui/src/toolbars/spec.rs`: the View tab's `view.display` group held four *planned* tools, so
  the ribbon captioned no Display group (`the_grid_snap_is_filed_under_its_own_snaps_caption` says so),
  and `ToolKind::Shadows`, its icon, the inventory row and the key were all missing.
- The same group is the last place a value could live: `GroupSpec` is tools only (U76 deleted
  `CellSpec::Field`), so a number has no cell to sit in.

## Decisions

- **The switch is the view's, the intensity is the workspace's.** `Leaf` gains `shadows: bool` beside
  `style`; `ViewSpec` gains `shadows: ContactShadows`, resolved by `ui::display::contact_shadows`
  from the workspace percent and the leaf's switch; `SceneFrame::contact_shadows` stays the fallback
  for the caller that draws the frame whole, exactly like `SceneFrame::shading` (ADR 0070). The
  plan's "one intensity control" and "the frame keeps colour, strength and the mask" both say the
  intensity is one value: four different darknesses in one workspace is a knob nobody wants.
- **The value sits in its own table, not in `GroupSpec`.** `spec::VALUES` (`GroupValue`,
  `ValueSpec`, `ValueKind`) names one number per group and `value_of(group)` is what the row reads;
  `show_value` draws the shared `Scrub` (ADR 0092) at `FIELD_WIDTH = 2 x RIBBON_CELL_WIDTH`, so the
  row keeps a whole-cell pitch (ADR 0067) and 26 `GroupSpec` literals did not grow a field that only
  one of them uses. This is narrower than U76's "no value fields": a tool's own parameters stay out of
  the toolbar, and a display amount with no other editor is the one exception, drawn where its
  switch is.
- **The intensity is written by the shell, on release.** The field reports
  `ToolAction::ShadowStrength { percent, settled }`; `ToolAction` is the ribbon's channel to the
  editor and `RibbonOutcome`/`RibbonViewAction` its channel to the shell, so `ui` still owns no
  setting. `Document::show_ribbon` returns `RibbonAsk` — the product card plus this value — and
  `Shell::ribbon` writes `settings.viewport.shadow_strength` at once (the frame reads the setting,
  so the drag is live) and calls `persist_settings` only when the gesture ends, so one drag is one
  write.
- **One key, `S`**, filed as the atom `view.display.shadows` in `crates/ui/src/inventory.rs` next to
  `view.snaps.grid`: the switch writes no document, leaves no undo entry and is not a command.
  `Ctrl+S` is save; a plain `S` was free.

## Ruled out

- A sixth `ShadingStyle` (taken as read by the plan): a shadow combines with all five face styles, so
  the list would have to hold ten and the cluster's five buttons become a matrix.
- Keeping the intensity in Settings and the switch in the ribbon: the owner asked for one control
  site, and a value whose control sits in another window than its switch is the two-home defect
  ADR 0117 exists for. `Reset display` still restores it, because it is still a workspace default.
- A split cell whose caret opens the intensity: the caret is the method list (`icons::ribbon_split_cell`,
  U74) and a value is not a method.
- A per-view `f32` strength: it would have to be persisted per leaf to survive a launch, and the leaf
  state is not in the workspace file; the settings field is, and the ask says one intensity.

## Evidence

`target/ui-shots/shadows-*.png` (`cargo test -p z3l --bin z3l -- --ignored the_shadow_is_per_view`):
the View tab's Display group in both themes and at 200 %, the same view with the switch off beside it
on, and a four-view workspace whose active front cell draws no shadow while the top and axonometric
cells keep theirs.
