# C3 — a contour node moves in a latched mode, with its distance and angle at the cursor

a contour node moves in a latched mode, with its distance and angle at the cursor

## What was measured

- `app/src/contour_gizmo.rs` moved a corner only while the primary button was held:
  `drag_started_by` resolved the grip, `dragged_by` moved it, `drag_stopped_by` cleared the drag, and
  the working copy waited for Enter. A click on a corner did nothing at all, and `handle_keys` sent
  every Escape in the mode straight to `cancel_contour_edit`.
- The only number a drag opened was `grip_field`: one plate of the grip's own measurement (a radius, a
  width, an angle), and nothing at all for a plain line corner — `ContourDraft::grip_number` answers
  `None` for an untagged line corner, so the drag of the corner this task is about had no number.
- `crates/ui/src/draw_fields.rs` already measured exactly one delta: `Shape::Segment` is a length from
  an anchor and an angle from `+X`, with the smaller-angle rule, the arc anchor and the `Reference`
  the guides draw. Nothing read a move, because a move had no anchor.
- `crates/ui/src/guides.rs` names the case in its own header: "a node's old position to the one under
  the pointer" is a construction line. The painter, the dash pattern and the two-stroke reference
  were all there; the move was not.
- `document.rs`'s `else { self.contour_gizmo.reset(); }` ran whenever `contour_editing` was false,
  which includes a pointer over a plate or a panel — the defect C2 fixed for the drawing tool
  (unfreezing the work plane) and left in the contour branch.
- The plates of a move are *not* at the point being placed. `latch_move` puts the length's plate at
  the chord's midpoint and the angle's on the arc, both within 16 points of the pointer at short
  distances, so `pointer_on_chrome` blocked the follow the moment the hand crossed one: measured as
  `field_contains(to)` true and the corner frozen at its old position.
- `handle_keys` runs before the viewport paints, so a key both the mode and a plate would read is
  decided by the first reader; the draw tool answers it with `holds_keys()`, and the contour gizmo
  had no such answer.

## Decisions

- The delta is `PointState::moved(anchor, pointer, fields)` in `draw_fields.rs`, not a second
  measurement in the shell: the same stage code gives the numbers, the anchors and the reference, so
  a moved node and a drawn segment cannot drift apart.
- The latch lives in the shell because it is view state (ADR 0029): `CornerLatch` holds the grip, the
  old position, the motion resolved once from the along toggle, the `FieldSet`, the last
  `PointState` and a `moved` flag. The working copy stays the editor's.
- `update` and `paint` return `GizmoAction` (`Idle`, `Changed`, `Numeric`, `Drop`, `Abandon`) so the
  gizmo keeps no session: the shell applies a typed number, drops a move and abandons one through
  the same path the Enter key takes.
- The drop is `apply_contour_edit` plus `start_contour_edit` on the same target: one command and one
  undo entry per corner, and the mode survives so the next corner is one click away from moving.
- A drop whose draft corner is still within a micrometre of the old position returns `Idle`, so a
  click that names nothing writes nothing, and no undo entry is minted.
- Escape is the latch's first: `abandon_latch` restores the corner with `contour_edit_move_corner_at`
  and clears a recorded collapse, and `handle_keys` falls back to `cancel_contour_edit` only when no
  latch was there.
- The latch resolves the pointer from `input.pointer.hover_pos()` when the scene's own hover is gone,
  and a press inside one of its plates never ends the move: the plates are the one chrome surface the
  move owns. The shell calls `update` while a latch is live even when the pointer is on chrome.
- A press that became a drag keeps the one-gesture move (`dragging` is `self.drag.is_some()` or a
  fresh `drag_started`), and the drag sets `selected`, so the click after a drag latches it.
- Only `ContourGrip::Corner` is latched; a figure's grips keep their press-and-drag, as the task says.

## Ruled out

- A second command for the move (`node.move`): the drop writes the working copy the mode already
  holds, so it is the one `object.path.replace` / `panel.outline.set` the mode always used.
- Measuring the delta in the shell with its own trigonometry: it duplicates ADR 0128's four-quadrant
  rule and ADR 0127's anchors, and the plate anchors would be a second copy of `arc_anchor`.
- Letting the latch end the mode on a drop: three corners would be three re-entries of the mode from
  the inspector card, which is the flow the latch exists to avoid.
- Making the plates of a move plain chrome: measured as a frozen move at short distances.
- Ending the drag on a click: a drag that ends in a click would latch and immediately drop, so
  `dragging` suppresses the click branch for the frame that ends a drag.

## Measured after the plan was filed

- No live look was taken: the guides and the ghost are asserted through the frame tests and the
  `theme` inks of ADR 0127, and the plate is the atom's existing frame.
