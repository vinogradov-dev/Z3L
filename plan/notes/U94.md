## What was measured

- Command ids: 57 `pub const *_ID` in `crates/engine/src` (re-measured; the first pass said 56), and
  `COMMANDS` in `crates/engine/src/commands.rs` holds the same 57 specs, the count its test asserts.
  Each spec is `CommandSpec::new(<ID>_ID, <ID>_LABEL, …)`, so the id and the words of a command are
  both resolvable from the source without linking the crate — which is what lets `xtask` compare the
  engine with the table.
- Three ids are named nowhere in `crates/ui` or `apps/furnicraft/src`: `panel.contour.create` (U90
  makes a ring panel through `panel.create` with an outline, so the free-outline cell commits that),
  `node.origin.rebase` and `node.property.set_many`.
- Ribbon map (`crates/ui/src/toolbars/spec.rs`): 29 live cells and 62 planned rows. A cell is keyed
  by a method id (`sketch.create.line`) and carries its own label and artwork; two cells can commit
  one command, and six cells commit `object.path.create`. The map is a lexicon, not a command list.
- Palette: `Palette::entries` lists all 57 specs and `params_for` answers 13 of them — twelve build
  parameters, `node.rename` answers with its refusal — and the other 44 print "needs a selection".
- Nothing joined the three registers: `ui-rules` read colours and hosts, the palette read the
  registry, the ribbon read its own map.

## Decisions

- The inventory is keyed by command id, and `places` records where the capability is reachable
  *today* — measured with `rg` over `crates/ui` and `apps/furnicraft/src`, not intended. `Api` is the
  one place that means no surface draws it, and it is exclusive: the gate refuses a row that claims
  both.
- `icon` is the glyph of the one button that draws the capability. A command reached through method
  cells (path create, primitive create, panel create) has no button of its own and carries `None`;
  its cells keep their words and art in the map. So the ADR's "planned row" lives in the map, and the
  gate refuses a live cell that names no artwork instead of rebuilding the ribbon from the table.
- `key` is a column from the start; only `node.delete` has one today (`Delete`), and U96 reads it.
- The three orphan ids are `Api`, each for its own measured reason. `panel.contour.create`
  duplicates `panel.create` with an outline, which is what the free-outline cell commits, and it goes
  to `plan/debt.md`. `node.origin.rebase` is the model operation for a re-anchor no surface offers
  yet. `node.property.set_many` is a batch: the properties card writes one field per edit so each
  edit has its own undo entry, and a batch is for the assistant and a CLI.
- The palette hides the `Api`-only rows. That is the first surface to filter the table, and it stops
  offering three commands that could never run from there.
- The gate resolves `static COMMANDS` the way the compiler would: `module::CONST` → the const in
  `crates/engine/src/<module>/` → the `CommandSpec::new(<ID>_ID, <LABEL>, …)` call → the id string
  and the `Message` behind the label const. It compares the command's own words with the row's.
- `ATOMS` is the declared place for a row keyed by a mechanism rather than a command (ADR 0118). It is
  empty today, and it keeps a typo in a command id a failure instead of a silently accepted atom.

## Ruled out

- Re-keying ribbon cells by command id, so the ribbon reads the table for its words: the six drawing
  cells commit one command and every cell is named after its method, so the ledger would have to hold
  six rows for `object.path.create` and the cell's word would still be the map's. The map stays the
  lexicon; U92 filters the table, and U91 edits the map.
- A `const fn` lookup for a cell's label: `str` comparison is not `const`, so a `ToolSpec` constant
  cannot take its words from `ROWS` at compile time. Reading at draw time means a HashMap of borrowed
  rows per frame for no gain.
- Reading every `*_ID` const instead of the registry list: a const that no spec registers would then
  demand a row, and the gate would name a command the engine cannot run.
- Failing on one icon file shared by two commands: ADR 0117 keeps that a review note, and a service
  action may legitimately reuse a drawing. The gate prints it.

## The cheap path

A five-line section in `docs/decisions/0117` saying a row is keyed by a *command* and a ribbon cell by
a *method*, so the next session does not spend 887 lines deciding whether the ribbon must read the
table. It belongs under "Consequences" of 0117.

## For the strategy

An empty order is not a defect and `cargo xtask next` lists the candidates, so the first thing a
session does is decide, not read — say which task and why in one line. The note of a queued task is
worth more than its entry: U94's numbers were one command away from correct, and only the note said
which registers had to be joined.
