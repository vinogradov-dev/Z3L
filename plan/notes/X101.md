# X101 — What was measured

## What was measured

- `crates/project/src/lib.rs` (`SceneFile::parse`) already read the document into a `serde_json::Value`
  and checked the number before typing it (d8d296c, 2026-11-20), so opening a scene file through the
  envelope answered the schema sentence. The unguarded door was the document's own reader.
- `crates/model/src/project/wire.rs` had `#[serde(try_from = "ProjectWire")]` on `Project`: serde
  builds `ProjectWire` first and reports a missing field at the end of the map, so the version branch
  in `TryFrom` ran only after the tree had already failed. `serde_json::from_str::<Project>(…)` on a
  body with no fields but another schema answered "missing field `revision`", not the version.
- Every app path reads a scene through `SceneFile::read` (`app/src/document.rs:560`, `app/src/cli.rs:658`,
  `cli/query.rs:133`, `cli/recipe.rs:61`, `cli/served.rs:33`, `cli/render.rs:47`), so the guard that was
  missing stands at the model boundary: model tests, the engine session test and any future reader of a
  bare document had no version sentence at all.

## Decisions

- The rule lives in the document reader. `impl Deserialize for Project` reads a `serde_json::Value`,
  calls `check_schema`, and only then types the tree through `ProjectWire`; `Project::from_value` is
  that function taking the value, so the envelope moves its value into it instead of having serde
  rebuild the tree once more — one JSON tree per file.
- `ProjectError::UnsupportedSchemaVersion::found` became a `String`: the file may carry no number or a
  value that is not one, and the sentence names what was found (`missing`, `27`, `"current"`) instead
  of reporting an invalid type or lying with a `u32`.
- The envelope keeps its own pre-check and its own error variant. It answers with the same sentence
  without the `invalid scene JSON:` prefix, and it fires before the document is entered at all; the
  document reader is what makes the rule hold for every other door.
- `#[serde(default)]` left `Project::active_camera`: it is optional in `ProjectWire`, which is the only
  shape the reader accepts, so the default moved with the field into the wire.

## Ruled out

- A `deserialize_with` on `ProjectWire::schema_version` that checks eagerly: it wins only when the
  number is read before a broken field, and loses to any type error that sits earlier in the map.
- A second variant `SchemaVersionMissing`: two sentences for one fact. `found` carries the word.
- `serde_json::value::RawValue` in the envelope: it keeps the raw text but parses the body twice, and
  the promise here is one tree, not two passes.
