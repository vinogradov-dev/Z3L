# J20 — the domain is taught, and a construction is composed

## What was measured

- `crates/mcp/src/server.rs::listing` answered five keys — revision, open product, mode, commands —
  and `command_row` said the id, the English label, the created level, `enabled` with its sentence and
  the schema. Nothing said which *world* a command serves, so a nut, a carcass and a light were three
  ids among 51 and only the label told them apart.
- `model::class::registry()` (`crates/model/src/class.rs:905`) holds 70 rows in eight families with
  slugs, labels and aliases, and no door published one of them: «стойка», «полка» and «штанга»
  (`20.06`) were readable only from the source. The rod has a class and no creation command.
- `Envelope` (`crates/model/src/container.rs:37`) carries a `Footprint` — rectangle, cut corners or a
  drawn ring — and `product.create` takes the whole envelope, so a radius frame corner was already
  possible and no sentence said so.
- ADR 0105's stance table was code only in the fill tool and the recorded wardrobe; the wardrobe's own
  mistakes were the missing words: millimetres for a micrometre field (X115), an origin above the
  board (X117), `left` on the viewer's right (X118).
- The registry's areas: `panel`, `product`, `assembly`, `object`, `contour`, `area`, `mesh`, `node`,
  `scene`, `camera`, `light` — eleven prefixes, and `assembly.create` was the one the first cut of the
  family table missed (the test caught it, not a review).

## Decisions

- **One value, one function.** `engine::guide()` returns the whole guide; `command_list` embeds it and
  `z3l guide` prints it. A second copy would be a second truth about what the program is for.
- **Generated where a table owns the answer.** The command lists come from `Family::commands()`, the
  classes from `model::class::registry()`, the frame example is an `Envelope` the model validates, the
  stances are one `Stance` table with the quaternions a placement stores. The prose is only what no
  table states: the order of a build, the rule that the domain wins, the units and the sides.
- **The family is derived from the id's area, not declared per command.** 51 hand-written fields
  would drift the day a command moved; one prefix table fails its test instead.
- **No `product.build`, no `carcass.box`.** ADR 0192's recipe is superseded (ADR 0215): a build is the
  commands a caller dispatches, and a batch makes it one call and one undo entry (ADR 0198, ADR 0214).
- **The fittings hole is said, not hidden.** No command creates a fitting; the guide names the classes
  and the fallback (a body in the geometry world) until the hardware family lands.
- The guide is about 15 KB of compact JSON. It rides on `command_list`, the call a client already
  makes first, so it costs no extra round trip.

## Ruled out

- **A sixth tool `domain_guide`.** Rejected: `command_list` is documented as "call this first", and a
  separate tool is one more name a client must be told about before it can learn anything.
- **An MCP resource.** `crates/mcp` serves tools only today; a resource would add a second protocol
  surface and a second test path for one constant value.
- **Writing the guide to `docs/domain/guide.md` and pointing a model at the file.** Rejected: a model
  in a window has no filesystem, and a paragraph a person edits drifts from the registry it describes.
- **Publishing the classes as a `query` instead of in the guide.** Rejected for now: the classes are
  the domain, not the scene, and the guide is read once while a query is per-question. A `classes`
  query can come later without moving this value.
- **`prototype.id` for the recipe record.** Dropped with the recipe: the owner left the prototype
  record to Q1, and `prototype.id` is a document `Id`, which a recipe name is not.
