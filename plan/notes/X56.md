# X56 — the world box of a drawable is the box its mesh was measured with

the world box of a drawable is the box its mesh was measured with

One edit anywhere used to cost the whole scene; it now costs the walk of the tree.

## What was measured

- Before, `Bounds::include_mesh` in `app/src/scene_build.rs` transformed every vertex of every mesh
  and `collect_panel`/`collect_object` called it twice — once into the subtree's `all` box and once
  into `solid`. 5 000 spheres of 32 x 16 are 896 vertices each, so one edit was 9 M transforms:
  27 / 109 / 285 ms at 500 / 2 000 / 5 000 objects, while a rebuild that changes nothing cost 24 ms
  at 5 000. The vertex pass was the whole difference.
- After, the local box is measured once with the mesh and kept on `NodeGeometry`, so a walk turns
  eight corners per drawable. Measured with the new probe
  (`app/src/scene_build.rs`, `an_edit_costs_the_walk_of_the_tree_and_not_the_vertices`, 32 x 16
  spheres, dev profile): an edit costs 0.42 / 3.6 / 18.4 ms at 500 / 2 000 / 5 000, identical to a
  rebuild that changes nothing (0.41 / 3.67 / 18.4 ms) — the walk of the tree at about 3.7 µs per
  node. Cold evaluation is unchanged: 0.58 / 2.2 / 5.5 s.
- `VERTICES_TRANSFORMED` (test-only thread-local in `app/src/scene_build.rs`) counts the vertices
  the per-vertex box has read. The probe asserts it stays at zero across five moves, so a session
  that puts the loop back into the walk fails even on a machine fast enough to hide it in the timing.

## Decisions

- **The box is a value in `geom`, measured once with the mesh.** `geom::Aabb` (`of_points`, `min`,
  `max`, `center`, `radius`, `union`, `transformed_by`, `corners`) is stored on `NodeGeometry` beside
  the mesh it belongs to, because it is derived from that mesh and rebuilt exactly when the mesh is.
  `app::Bounds` became an accumulator over `Option<Aabb>` instead of a second min/max/valid copy.
- **One world box feeds `all` and `solid`.** Both boxes held the same content for a solid, so
  `SubtreeBounds::include_solid` turns the corners once and merges both; the container boxes still
  come from the children and a drawing still contributes to `all` only.
- **`MeshData::local_bounds` is now the only place that reads vertices**; `Bounds::include_mesh`
  survives as a `#[cfg(test)]` reference, which is what the equivalence test compares against.
- **The corner box is the box of the turned box.** It is exact for a translation and for any turn
  that maps an axis to an axis — a quarter turn is every panel and every `Placement::IDENTITY`
  object, and that is the whole demo scene — and it is exact for a turned rectangle at any angle,
  because a rectangle's extremes are its corners.
- **`band_bounds` is `Vec<Option<Aabb>>`, not a filtered `Vec<Aabb>`.** `tessellate_panel` rejects a
  mesh with no vertex, so the box is always measured; the `Option` keeps the list aligned with
  `bands` instead of silently shortening it.

## Ruled out

- **Keeping the tight world box keyed by (mesh, placement) on the cache entry.** It tightens only
  tilted round and notched bodies, and it costs a placement key plus a per-vertex pass on every
  moved node — the Done clause asks for a rebuild that transforms no vertex, and the moved node's
  whole subtree would pay it.
- **A second, tighter box for the contact shadows only.** `ContactShadow::from_bounds` reads the
  solid box and refuses a body whose box is more than `FLOOR_TOLERANCE_MM` (0.5 mm) off the floor,
  so the loose box does change a shadow: a ball turned 30° about X keeps a tight `min.z` of 0
  because a ball is round, while its corner box dips to -34.15 mm on a 50 mm ball, so the shadow
  disappears; a body that keeps one gets the ellipse of the box of its box. Filed as X62 with the
  placement-keyed box as its shape.
- **Storing the local box on `MeshData`.** The struct is built by the kernel adapter, the primitive
  mesher and a hundred test literals; the value belongs to the cache entry that already owns the
  mesh and its edge lists.
