# X100 — a contour set is extruded one body per ring

The Extrude cell turned a path into a body and nothing turned a contour set into bodies, so a maker
who built a shape out of three drawings could not use it.

## What was measured

- `crates/engine/src/object_cmds.rs:290` — `object_path_extrude_enabled` read `Project::object_path`,
  so the command refused every node that was not a path; X100's first half was still true.
- The second half was stale: since `de2396d` (21.11, ADR 0205) `crates/ui/src/toolbars/ready.rs:100`
  did not switch the cell off on a set — it armed the area pull, `ToolActivity::AreaPull` drew the
  cell pressed, and the pointer named one face of the drawing. The entry was filed on 20.11, one day
  before G4 landed, and its "the Extrude cell goes off" sentence no longer held.
- `model::Contours::new` (`crates/model/src/object.rs:402`) validates every ring through
  `Path::to_contour`, which refuses a self-crossing ring; `Path` itself stores a chain without that
  check, because self-intersection is a ring rule.
- `param::validate_extrusion_contour` refuses a ring whose samples exceed `MAX_FACE_VERTICES = 1024`
  after up to six doublings of the chord (`crates/param/src/profile.rs:68`), which is the other
  refusal a stored ring can meet.
- `Project::add_object` bumps the revision itself, and `allocate_ids` reserves a run of ids before any
  tree mutation — the shape a single-revision multi-node write needs.

## Decisions

- **Widen the command, not the surface.** `object.path.extrude` takes a path node or a contour set
  node; the stable id, the cell and the parameters are unchanged, because both payloads are one
  drawing and the press means the same thing (`ADR 0220`).
- **The first ring keeps the node.** `Project::extrude_object_contours` converts the node in place and
  lands the other rings beside it in the drawing's frame, named `Union`, `Union 2`, with a pivot of
  zero. One revision, one undo entry, and a batch's `$ref` and the selection still name one node.
- **The area pull is the cell's second method.** The cell is a split cell: the main face extrudes the
  whole drawing, the list offers `object.area.extrude` under its own glyph
  (`assets/icons/bodies/pull-area.svg`). Readiness is decided per `ToolKind`, so no second dispatch
  path appeared; `ToolKind::AreaPull` is the second kind.
- **The area method is off for a path.** One ring has no areas, and `object.area.extrude` requires
  `Geometry::Contours`; the row says what to select instead of arming a pointer that can only refuse.

## Ruled out

- **A command of its own (`object.set.extrude`).** The press, the payload and the height are the same
  ones; a second id would have taken an inventory row, a place and an API address for one drawing.
- **Removing the body of the set and creating every ring as a new object.** Nothing would carry the
  selection, the undo entry or a batch's name; the in-place first ring costs one line more.
- **A single body with two profiles.** The kernel's extrusion takes one ring, and a solid of two
  disconnected pieces is not a part a shop cuts (`ADR 0220`).
- **A test for the per-ring mesh cap refusal.** A ring that trips the cap must be self-crossing before
  it is detailed — the spiky fixture that would trip it is refused by `Contours::new` as
  `SelfIntersecting` — so no legal set can hold such a ring: the loop over
  `validate_extrusion_contour` stays as the guard for a profile with holes and cannot be reached
  from a stored set today. Recorded in `ADR 0220`'s consequences.

## Left open

- A maker who extrudes a *nested* set gets one solid per ring — the block and the filler — rather than
  the frame between them. That is the literal reading of "a ring is a profile" and the area pull is
  the door to the frame; the profile with holes (G5) is the task that makes the frame one body.
