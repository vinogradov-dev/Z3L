## What was measured

- The review's own numbers: six logged tasks, ~119 minutes, 62 of them on one feature built three
  times, 22 of those repair. Both repairs blame `done` (a test that asserts the implementation) and
  `contract` (a routed skill that was never read).
- The old log format cannot be summed: `dead-end` was a phase and also inside `read`/`test`/`edit`,
  so U88's shares reach 103 % and U89's 128 %. U88 also wrote four stamps ahead of the clock.
- `plan-task.md` said "the tests that would fail before the change and pass after" — a sentence a
  test of the implementation satisfies, which is precisely how U88's `Crosshair` assertion passed.

## Decisions

- `+m` deltas replace both the clock stamp and the separate `cost` column: one field instead of two,
  no command per line, and the column sums to the total by construction, so no stamp can be written
  out of order.
- `dead-end`, `red-mine`/`red-tree` and `guessed` are attributes, never phases. A loss counted twice
  is a loss no column can read, which is the defect this file just measured.
- The phases gain `start`, `owner` and `close`, because the review had three blind spots: when the
  session began, which turns came from a person, and what landing the work costs apart from the edit.
- `plan-task`'s `Shape` may name a command id only with what its parameters accept — U90's entry
  prescribed `panel.contour.create` for a drawn ring and the session had to re-decide it (ADR 0114).
- The routed skill is named in `/next-task`'s Start step, not in `AGENTS.md`: §1.3 already routes it,
  and a second copy of the route is the drift the review is meant to remove.

## Ruled out

- **A scraper or a metrics command.** Six tasks are not a series; the format is readable through
  `cargo xtask task <ID>` and a tool would freeze a vocabulary that is still moving.
- **Rewriting the 73 notes that predate the format.** They are history, and their minutes cannot be
  reconstructed honestly.
- **One more rule per finding.** Every change replaces a sentence that is already there; the four
  prompt files grew by 25 lines and lost 14.
- **Touching `AGENTS.md`.** Its only change this period (§8, expertise leads) is already in the tree
  and is the one rule that would have prevented X42.

## The cheap path

The review found the mechanisms and this task wrote them down; what it could not do is make the next
session obey. The one edit that pays fastest is the Phase-tally promise in `/time-review`: a session
that reads `+m` as "minutes since the last line" gets an additive table for free, where the clock
stamp needed a second column and a guess.

The refusal that closed this task is P15's own evidence, measured by the session that filed it: the
budget message printed the count but not that it counts the candidate, so a `--next` two lines longer
than the paragraph it replaces is refused as if the file had grown by that much. That is the exact
shape of U88's seven minutes — the tool compares three numbers and prints one.

## For the strategy

The instruction files are now four, and every one of them is read at a different moment: `/plan-task`
before the work exists, `/next-task` before the first edit, `/fix` after the defect, `/time-review`
after six tasks. A rule that is not in the file read at the right moment does not exist — that is the
whole finding of the period, stated once.
