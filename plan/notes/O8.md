# O8 — A price names its money and its source; stock is an overlay

## What was measured

- `crates/catalog/src/money.rs` had `Money` (a `u64` of minor units) and `Currency` (code plus minor
  scale), and `PropertyValue::Money(Money)` stored the amount alone: no currency, no source, no date.
  A priced record was therefore unreadable outside the one directory that named a currency.
- `Directory.currency` was a field only the starter package ever set (`Starter::currency`); no package
  file carried a currency at all, so a folder written by a workshop lost it.
- `PriceUnit` existed as four `Trait`s and no type: nothing turned `price-sheet` into "one price buys
  a sheet", and a kind could carry two of them with nothing noticing.
- `docs/domain/nomenclature.md` §11 and ADR 0148 ask for more than the code had: provenance on every
  price, stock as an overlay package, external systems from a registry, a freshness notice.
- Nothing imported prices: `crates/catalog` had no CSV reader, no batch write and no notion of a
  history entry. `FolderWriter::save_item` builds the candidate directory per call and bumps the
  manifest once — the only "history" a directory has is its revision (`§13`).

## Decisions

- **`PropertyValue::Money(Price)`**, not the amount alone: `Price { minor, currency, source, date }`.
  The currency becomes unrepresentable when absent, which is exactly ADR 0120's "refuses a priced
  material while it names no currency" — the refusal moves from a load rule to the type.
- **The unit is not stored.** `PriceUnit::of(&Kind)` reads the kind's trait, `Directory::price`
  answers `PriceView { price, unit }`, so a record cannot disagree with its kind about what a price
  buys. `Kind::new` refuses two price traits: two would leave the reading to file order.
- **`Directory::currency()` is derived** from the priced records, and `MixedCurrency` refuses a
  directory that names two. The export's `money` block therefore still has one answer, unchanged.
- **A price a person typed has no date.** The directory carries no clock (§11): an import dates what
  it writes, a card that rewrites the amount turns `Imported` into `Typed` and drops the old date,
  and a card that only renames a record keeps the imported price untouched.

- **The batch's "history entry" is the revision.** A directory's history is its revision (§13: one
  bump per committed write), so `FolderWriter::save_items` validates the whole batch once and bumps
  the package's manifest once — a batch of forty prices is one entry, not forty. A batch that prices
  records of two packages is one entry per package, because a package's manifest is its own history.
- **The price list is `system,key,price_minor,currency,date`.** The anchor is the item's foreign key
  (§5.3, "nothing is matched by name"), so a typo lands on no record instead of on another one. The
  header is fixed and read by position: a moved column would write a currency where a price belongs.
- **Age is a comparison of two dates.** `Price::freshness(today, limit)` is pure; the card takes the
  day and the workshop's limit from the shell (`DirectoryEditor::set_price_aging`), and the order
  package judges every price against its own `exported_at` and writes `price_date` and `price_stale`.
  A typed price has no date, so it is `Undated` — a clock the directory does not have is not a reason
  to call a number old.

## Ruled out

- **A provenance side table keyed by `(ItemId, PropertyCode)`** — a second place a price could hide,
  and a save would have to keep two files agreeing.
- **Keeping `Directory.currency` as a field** — two sources of truth for one money.
- **A `PriceUnit` inside the value** — derived data in a package file, which §4.2 forbids.
- **A `history.jsonl` in the package** — a second file to keep in step with the records, for a fact the
  revision already carries; the owner's phrase "one history entry" is the one commit, not one file.
- **Matching a price row by `ItemId` or by name** — an id is the workshop's key and a name is nothing
  (§5.3); a supplier's list carries its own article, which is why the foreign key registry came first.
- **A zero for a record no overlay counts** — a zero is a count somebody measured; a workshop may know
  a material it does not stock.
- **Judging an order package's prices by the clock read at open time** — a package is a frozen copy, so
  one file must not say two things about the same price.
