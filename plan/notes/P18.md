# P18 — a decision is cited by its number, so two records may not share one

## What was measured

- `docs/decisions/` held 217 records for 216 numbers: `0104-a-ghost-of-a-missing-node-is-shell-paint.md`
  and `0104-supply-names-four-sources.md` both carried 0104, and `docs/decisions/README.md` listed
  both rows. The numbering is otherwise contiguous, 0001 to 0216, so the next free number is 0217.
- The check compared numbers alone. `check_in` collected file numbers into a `Vec<String>`, and the
  index loop pushed a row's number only `if !listed.contains(&number)` — the dedup hid a second row,
  and no comparison of the file list could see two files with one number, because a `Vec` of numbers
  is exactly what two files of one number produce once. `cargo xtask docs` answered `docs: ok` over
  the clash for as long as it existed.
- Twelve references meant the supply record rather than the ghost: `PROJECT.md` §"class",
  `docs/domain/classes.md` (three rows and rules), `crates/model/src/class.rs`'s `Supply` doc,
  `plan/questions.md`, `plan/notes/T1.md`. Nine meant the ghost and stay at 0104: the record itself,
  its index row, ADR 0157 twice, `docs/domain/products.md`, `app/src/box_gizmo.rs`, `plan/map.md`
  and the notes N6, N23, V2.
- The cost was real, not theoretical: the close of Y2 numbered its record 0214 because 0213 was
  already taken in the render worktree, and a session that reads "ADR 0104" in `crates/model/src/class.rs`
  opened the ghost record.

## Decisions

- The supply record takes 0217, because it is the newer of the two and fewer references name it; the
  ghost record keeps 0104, which is the number every reference in the interface code already meant.
- The index row moves to the end of the table rather than staying at 0104's place: the table is one
  ascending list, and a row out of order is the same rot the gate exists to reject.
- `shared` is one helper over `(number, name)` pairs and runs twice: once over the files, once over
  the index rows. Both files and rows keep their second field (the file name, the link target) so a
  violation names what a reader has to change, rather than only the number.
- A row naming a number no file carries is reported once even when the table lists it twice. The
  clash has its own sentence; repeating "no file carries that number" once per row adds nothing.

## Ruled out

- Keeping both records and disambiguating by title: a number is what the tree cites, in code
  comments and in `plan/`, and none of those carry a title.
- Renumbering both and repairing every reference: it turns nine correct references into work for no
  gain, and the ghost record's number is the one spoken in the interface.
- A fifth column in the index naming the record's subject: the number already is the identity, and a
  second name would have to be kept in step with the file's own title.
